# Recursividad

La recursividad es una técnica de programación en la que **una función se llama a sí misma** para resolver un problema. En Elixir se utiliza con frecuencia para procesar colecciones de datos y cadenas, así como para resolver problemas matemáticos y algorítmicos.

## ¿Por qué recursividad en la programación funcional?

En los **lenguajes funcionales** como Elixir, la recursividad es una herramienta fundamental para repetir operaciones y procesar datos. A diferencia de los bucles tradicionales de otros lenguajes, una función recursiva puede expresar la repetición mediante llamadas sucesivas a la misma función.

Esto resulta especialmente útil en Elixir por varias razones:

1. **No hay variables mutables**: los datos no se modifican después de haber sido creados. Por ejemplo, no es posible actualizar un contador mediante una expresión como `i++`. En una función recursiva, el nuevo valor se pasa como argumento en la siguiente llamada.
2. **Permite expresar el problema de forma declarativa**: en lugar de describir paso a paso cómo avanzar en un recorrido, se define qué debe ocurrir para cada caso del problema y cómo se continúa con una versión más pequeña o sencilla del mismo.
3. **Puede optimizarse**: cuando una función recursiva está escrita de determinada manera, el lenguaje puede optimizar las llamadas para evitar que cada una requiera espacio adicional en la pila. Esta técnica se conoce como **recursividad de cola** y se estudiará más adelante.

## Conceptos clave

Una función recursiva se basa principalmente en dos conceptos:

* **Caso base**: condición que **detiene** la recursión. Sin un caso base, las llamadas continuarían indefinidamente.
* **Caso recursivo**: parte de la función en la que se realiza una nueva llamada a sí misma. Esta llamada debe modificar el problema de manera que **se acerque al caso base**.

## Ejemplos Clásicos de Recursividad

A continuación, se presentan ejemplos típicos de funciones recursivas y su implementación en Elixir. Cada ejemplo es un programa completo. Guárdelo en su propio archivo `.exs` y ejecútelo con `elixir nombre_del_archivo.exs`.

### 1. Factorial

El factorial de un número se calcula como el producto de todos los enteros positivos desde 1 hasta ese número.

$$
n! = n \cdot (n-1) \cdot (n-2) \cdot \cdots \cdot 2 \cdot 1
$$

Como 5! = 5 · 4!, el factorial también puede definirse en términos del factorial del número anterior:

$$
n! =
\begin{cases}
1, & \text{si } n = 0, \\
n \cdot (n-1)!, & \text{si } n > 0.
\end{cases}
$$

**Implementación en Elixir:**

```elixir
defmodule Matematicas do
  def main do
    IO.puts(factorial(5))     # => 120
    IO.inspect(factorial(-3)) # => {:error, "El factorial no está definido para números negativos"}
  end

  # Caso base: el factorial de 0 es 1
  def factorial(0), do: 1

  # Caso recursivo: n! = n × (n-1)!
  def factorial(n) when n > 0, do: n * factorial(n - 1)

  # Manejo de errores
  def factorial(n) when n < 0 do
    {:error, "El factorial no está definido para números negativos"}
  end
end

Matematicas.main()
```

**Traza de ejecución para `factorial(5)`:**

```
factorial(5)
= 5 * factorial(4)
= 5 * (4 * factorial(3))
= 5 * (4 * (3 * factorial(2)))
= 5 * (4 * (3 * (2 * factorial(1))))
= 5 * (4 * (3 * (2 * (1 * factorial(0)))))
= 5 * (4 * (3 * (2 * (1 * 1))))   ← caso base

Ahora empezamos a resolver:

= 5 * (4 * (3 * (2 * 1)))
= 5 * (4 * (3 * 2))
= 5 * (4 * 6)
= 5 * 24
= 120
```

#### La pila de llamadas (****call stack****)

En la traza, cada llamada a `factorial` queda pendiente hasta que la siguiente llamada devuelve un resultado. Por ejemplo, `factorial(5)` no puede completar la operación `5 * factorial(4)` hasta conocer el resultado de `factorial(4)`. Lo mismo ocurre con las demás llamadas hasta llegar a `factorial(0)`.

Para poder continuar la ejecución posteriormente, el programa almacena la información necesaria de cada llamada en un **marco de pila** (**stack frame**), que contiene, entre otros datos:

* Los **parámetros** recibidos en la llamada, en este caso, el valor de `n`.
* El **punto de retorno**, que indica dónde debe continuar la ejecución cuando la llamada termine. En este ejemplo, corresponde a la multiplicación que debe realizarse con el valor retornado.

Estos marcos se almacenan en la **pila de llamadas** (**call stack**), que sigue una estructura LIFO (**Last In, First Out**), en la que el último marco en entrar es el primero en salir. Cada llamada a una función agrega un nuevo marco en la parte superior de la pila. Cuando la función termina, su marco se elimina y la ejecución continúa en el marco anterior.

Al llegar a `factorial(0)`, hay seis marcos en la pila, uno por cada llamada, y cada uno conserva su propio valor de `n`. Cuando `factorial(0)` devuelve `1`, los marcos comienzan a eliminarse en orden inverso. Cada llamada utiliza el resultado recibido para completar la multiplicación que había quedado pendiente.

> ⚠️ **Importante:** La pila de llamadas tiene un **tamaño limitado**. Por eso, una recursión demasiado profunda puede agotar el espacio disponible y producir un **stack overflow**. Una función recursiva que no tenga un caso base también continuará realizando llamadas hasta agotar este espacio.

### 2. Fibonacci

La secuencia de Fibonacci es una serie de números en la que cada número es la suma de los dos anteriores. La definición formal de la secuencia es:

$$
F(n) = \begin{cases}
0 & \text{si } n = 0 \\
1 & \text{si } n = 1 \\
F(n-1) + F(n-2) & \text{si } n > 1
\end{cases}
$$

**Implementación en Elixir:**

```elixir
defmodule Matematicas do
  def main do
    IO.puts(fibonacci(5))  # => 5
    IO.puts(fibonacci(10)) # => 55
  end

  def fibonacci(0), do: 0
  def fibonacci(1), do: 1
  def fibonacci(n) when n > 1, do: fibonacci(n - 1) + fibonacci(n - 2)
end

Matematicas.main()
```

Esta vez hay dos casos base, `fibonacci(0)` y `fibonacci(1)`, porque el caso recursivo necesita los dos valores anteriores.

**Traza de ejecución para `fibonacci(5)`:**

Cada llamada se abre en dos, y la respuesta de cada una se resuelve de abajo hacia arriba a medida que se llega a los casos base:

```
                                                            fibonacci(5)=5
                                         _________________________|___________________________________________
                                         |                                                                   |
                                   fibonacci(4)=3                                                       fibonacci(3)=2
                        _________________|_________________________                                 _________|_________________
                        |                                         |                                 |                         |
                  fibonacci(3)=2                             fibonacci(2)=1                   fibonacci(2)=1             fibonacci(1)=1
               _________|_________________                ________|_________                ________|_________
               |                         |                |                |                |                |
         fibonacci(2)=1            fibonacci(1)=1   fibonacci(1)=1   fibonacci(0)=0   fibonacci(1)=1   fibonacci(0)=0
       ________|_________
       |                |
fibonacci(1)=1   fibonacci(0)=0
```

Aunque esta implementación es simple y directa, no es la más eficiente debido a la recomputación de valores (observe cómo `fibonacci(2)` o `fibonacci(3)` se calcula varias veces). El número total de llamadas está dado por la fórmula `2 · F(n+1) − 1`, lo que hace que el tiempo de ejecución crezca **exponencialmente**:

| Llamada         | Número de invocaciones a `fibonacci/1` |
| --------------- | -------------------------------------- |
| `fibonacci(10)` | 177                                    |
| `fibonacci(20)` | 21.891                                 |
| `fibonacci(30)` | 2.692.537                              |
| `fibonacci(40)` | 331.160.281                            |
| `fibonacci(50)` | 40.730.022.147                         |

Es decir, calcular `fibonacci(50)` con esta implementación requiere más de **cuarenta mil millones** de llamadas. Cada vez que `n` aumenta en 10, el costo se multiplica aproximadamente por 123.

### 3. Potencia

La potencia de un número se calcula como el producto de ese número por sí mismo un cierto número de veces. La definición formal es:

$$
a^n = \begin{cases}
1 & \text{si } n = 0 \\
a \cdot a^{n-1} & \text{si } n > 0
\end{cases}
$$

**Implementación en Elixir:**

```elixir
defmodule Matematicas do
  def main do
    IO.puts(potencia(2, 4)) # => 16
  end

  def potencia(_, 0), do: 1 # Caso base
  def potencia(a, n) when n > 0, do: a * potencia(a, n - 1) # Caso recursivo
end

Matematicas.main()
```

La traza tiene la misma forma que la del factorial. Escríbala para `potencia(2, 4)` y compruebe que llega a 16.

### 4. Multiplicación (mediante sumas)

La multiplicación de dos números se puede definir de manera recursiva como la suma repetida de uno de los números. La definición formal es:

$$
mult(a, b) = \begin{cases}
0 & \text{si } b = 0 \\
a + mult(a, b-1) & \text{si } b > 0
\end{cases}
$$

**Implementación en Elixir:**

```elixir
defmodule Matematicas do
  def main do
    IO.puts(multiplicar(3, 4)) # => 12
  end

  def multiplicar(_, 0), do: 0
  def multiplicar(a, b) when b > 0, do: a + multiplicar(a, b - 1)
end

Matematicas.main()
```

**Traza para `multiplicar(3, 4)`:**

```
multiplicar(3, 4)
= 3 + multiplicar(3, 3)
= 3 + (3 + multiplicar(3, 2))
= 3 + (3 + (3 + multiplicar(3, 1)))
= 3 + (3 + (3 + (3 + multiplicar(3, 0))))
= 3 + (3 + (3 + (3 + 0)))   ← caso base

Ahora empezamos a resolver:

= 3 + (3 + (3 + 3))
= 3 + (3 + 6)
= 3 + 9
= 12
```

## Recursividad con Cadenas

La recursividad también puede aplicarse a cadenas de texto. En cada llamada se separa un carácter del resto de la cadena mediante funciones del módulo `String`, se procesa ese carácter y se invoca la función con el resto, que es una cadena más corta. El caso base es la cadena vacía, `""`.

### 1. Invertir una cadena

Por ejemplo, podemos implementar una función que invierta una cadena de la siguiente manera:

```elixir
defmodule Cadenas do
  def main do
    IO.puts(invertir("hola")) # => aloh
  end

  # Caso base: cadena vacía
  def invertir(""), do: ""

  # Caso recursivo
  def invertir(cadena) do
    # Separar último carácter del resto
    ultimo = String.last(cadena)
    resto = String.slice(cadena, 0..-2//1) # Obtener todo menos el último carácter

    # Último + invertir(resto)
    ultimo <> invertir(resto)
  end
end

Cadenas.main()
```

**Traza para `invertir("hola")`:**

```
invertir("hola")
= "a" <> invertir("hol")
= "a" <> ("l" <> invertir("ho"))
= "a" <> ("l" <> ("o" <> invertir("h")))
= "a" <> ("l" <> ("o" <> ("h" <> invertir(""))))
= "a" <> ("l" <> ("o" <> ("h" <> "")))   ← caso base

Ahora empezamos a resolver:

= "a" <> ("l" <> ("o" <> "h"))
= "a" <> ("l" <> "oh")
= "a" <> "loh"
= "aloh"
```

>**⚠️ Nota:** El módulo `String` ya cuenta con la función `String.reverse/1` que invierte una cadena de texto de manera eficiente, pero es útil entender cómo funciona la recursión en este contexto.

### 2. Contar vocales

En este ejemplo, implementamos una función que cuenta el número de vocales en una cadena:

```elixir
defmodule Cadenas do
  def main do
    IO.puts(contar_vocales("Mundo")) # => 2
  end

  def contar_vocales(""), do: 0

  def contar_vocales(cadena) do
    primer_caracter = String.first(cadena)
    resto = String.slice(cadena, 1..-1//1) # Obtener todo menos el primer carácter

    if es_vocal?(primer_caracter) do
      1 + contar_vocales(resto)
    else
      contar_vocales(resto)
    end
  end

  defp es_vocal?(c), do: c in ["a", "e", "i", "o", "u", "A", "E", "I", "O", "U"]
end

Cadenas.main()
```

**Traza para `contar_vocales("Mundo")`:**

```
contar_vocales("Mundo")
= contar_vocales("undo")          (M no es vocal, no suma)
= 1 + contar_vocales("ndo")       (u es vocal, suma 1)
= 1 + contar_vocales("do")        (n no es vocal, no suma)
= 1 + contar_vocales("o")         (d no es vocal, no suma)
= 1 + (1 + contar_vocales(""))    (o es vocal, suma 1)
= 1 + (1 + 0)                     ← caso base

Ahora empezamos a resolver:

= 1 + 1
= 2
```

## Recursividad con Listas

La recursividad es la forma habitual de procesar listas en Elixir. Aunque el módulo `Enum` ya proporciona muchas funciones para recorrerlas y transformarlas, implementarlas manualmente permite entender mejor cómo se construyen estas operaciones.

Las listas son estructuras naturalmente recursivas en Elixir, porque una lista es un primer elemento seguido de **otra lista**. Esa forma se escribe `[head | tail]`, donde `head` es el primer elemento y `tail` es el resto. La clave para la recursión está en que `tail` **siempre es una lista**, incluso cuando queda vacía, así que la misma función puede volver a aplicarse sobre él.

Por ejemplo, la lista `[1, 2, 3]` se puede descomponer paso a paso de la siguiente manera:

```
[1, 2, 3]   se parte en   head = 1,  tail = [2, 3]
   [2, 3]   se parte en   head = 2,  tail = [3]
      [3]   se parte en   head = 3,  tail = []
       []   no tiene head, es el caso base
```

Cada llamada recursiva recibe el `tail` como nueva lista, acercándose al caso base (`[]`) en cada paso.

Esa descomposición es **coincidencia de patrones**, la misma que se ha usado con tuplas y mapas, y por eso tiene un límite. Una lista vacía no tiene cabeza que asignar, así que el patrón falla:

```elixir
[head | tail] = []
# ** (MatchError) no match of right hand side value: []
```

Por eso toda función recursiva sobre listas necesita una cláusula aparte para `[]`.

### 1. Sumar elementos

Por ejemplo, podemos definir una función que sume todos los elementos de una lista.

```elixir
defmodule Listas do
  def main do
    IO.puts(sumar([1, 2, 3])) # => 6
  end

  # Caso base: la suma de una lista vacía es 0
  def sumar([]), do: 0

  # Caso recursivo: se suma el head al resultado de sumar el resto de la lista (tail)
  def sumar([head | tail]), do: head + sumar(tail)
end

Listas.main()
```

**Traza para `sumar([1, 2, 3])`:**

```
sumar([1, 2, 3])
= 1 + sumar([2, 3])
= 1 + (2 + sumar([3]))
= 1 + (2 + (3 + sumar([])))
= 1 + (2 + (3 + 0))   ← caso base

Ahora empezamos a resolver:

= 1 + (2 + 3)
= 1 + 5
= 6
```

### 2. Contar elementos pares

En este otro ejemplo se cuentan los números pares de una lista. Un *guard* verifica si cada número es par.

```elixir
defmodule Listas do
  def main do
    IO.puts(contar_pares([1, 2, 3, 4, 5])) # => 2
  end

  def contar_pares([]), do: 0
  def contar_pares([head | tail]) when rem(head, 2) == 0, do: 1 + contar_pares(tail) # Solo se cuenta si el residuo es 0
  def contar_pares([_head | tail]), do: contar_pares(tail) # No se cuenta si es impar, pero se sigue recorriendo la lista
end

Listas.main()
```

**Traza para `contar_pares([1, 2, 3, 4, 5])`:**

```
contar_pares([1, 2, 3, 4, 5])
= contar_pares([2, 3, 4, 5])            (1 es impar)
= 1 + contar_pares([3, 4, 5])           (2 es par)
= 1 + contar_pares([4, 5])              (3 es impar)
= 1 + (1 + contar_pares([5]))           (4 es par)
= 1 + (1 + contar_pares([]))            (5 es impar)
= 1 + (1 + 0)                           ← caso base

Ahora empezamos a resolver:

= 1 + 1
= 2
```

### 3. Encontrar el máximo

En este caso se encuentra el valor máximo de una lista de números, comparando cada elemento con el mayor encontrado hasta ese momento.

```elixir
defmodule Listas do
  def main do
    IO.inspect(maximo([3, 1, 4, 1, 5, 9])) # => 9
    IO.inspect(maximo([]))                 # => {:error, :lista_vacia}
  end

  def maximo([]), do: {:error, :lista_vacia} # No existe máximo en una lista vacía
  def maximo([head | tail]), do: maximo(tail, head) # Se inicia la búsqueda con el primer elemento como el mayor

  defp maximo([], mayor), do: mayor # Caso base: si la lista está vacía, se devuelve el mayor encontrado
  defp maximo([head | tail], mayor) when head > mayor, do: maximo(tail, head) # Si el head es mayor, se actualiza el mayor
  defp maximo([_head | tail], mayor), do: maximo(tail, mayor) # Si no, se sigue con el mismo mayor y se sigue recorriendo la lista
end

Listas.main()
```

Este ejemplo necesita un parámetro adicional para llevar el mayor valor encontrado hasta el momento. Como no hay variables que se puedan modificar, ese valor tiene que viajar como argumento de una llamada a la siguiente.

La función pública `maximo/1` incluye una cláusula para la **lista vacía**, que retorna `{:error, :lista_vacia}`. Sin ella, llamar a `maximo([])` provocaría un error, ya que ningún patrón coincidiría.

**Traza para `maximo([3, 1, 4, 1, 5, 9])`:**

```
maximo([3, 1, 4, 1, 5, 9])           ← llamada pública, inicia mayor = 3
→ maximo([1, 4, 1, 5, 9], 3)         (1 < 3, mayor sigue siendo 3)
→ maximo([4, 1, 5, 9], 3)            (4 > 3, mayor se actualiza a 4)
→ maximo([1, 5, 9], 4)               (1 < 4, mayor sigue siendo 4)
→ maximo([5, 9], 4)                  (5 > 4, mayor se actualiza a 5)
→ maximo([9], 5)                     (9 > 5, mayor se actualiza a 9)
→ maximo([], 9)                      (lista vacía, caso base)
→ 9
```

### 4. Filtrar elementos

En este ejemplo, se filtran los elementos de una lista que son mayores a un cierto valor límite.

```elixir
defmodule Listas do
  def main do
    IO.inspect(filtrar_mayores([1, 5, 3, 8, 2], 3)) # => [5, 8]
  end

  # Caso base: si la lista está vacía, se devuelve una lista vacía
  def filtrar_mayores([], _limite), do: []
  
  # Caso recursivo: si el head es mayor que el límite, se incluye en el resultado
  def filtrar_mayores([head | tail], limite) when head > limite do
    [head | filtrar_mayores(tail, limite)]
  end
  
  # Caso recursivo: si el head no es mayor, se omite y se sigue con el tail
  def filtrar_mayores([_head | tail], limite) do
    filtrar_mayores(tail, limite)
  end
end

Listas.main()
```

Hasta aquí `[head | tail]` se había usado solo para **descomponer** una lista. En este ejemplo aparece por primera vez en el sentido contrario: `[head | filtrar_mayores(tail, limite)]` **construye** una lista nueva, poniendo `head` al frente de lo que devuelva la llamada recursiva. Para distinguir los dos usos basta con mirar dónde aparece. En los parámetros de la función parte la lista que llega, y dentro del cuerpo arma la lista que se devuelve.

**Traza para `filtrar_mayores([1, 5, 3, 8, 2], 3)`:**

```
filtrar_mayores([1, 5, 3, 8, 2], 3)
= filtrar_mayores([5, 3, 8, 2], 3)                (1 > 3 es falso, se omite)
= [5 | filtrar_mayores([3, 8, 2], 3)]             (5 > 3 es verdadero, se incluye)
= [5 | filtrar_mayores([8, 2], 3)]                (3 > 3 es falso, se omite)
= [5 | [8 | filtrar_mayores([2], 3)]]             (8 > 3 es verdadero, se incluye)
= [5 | [8 | filtrar_mayores([], 3)]]              (2 > 3 es falso, se omite)
= [5 | [8 | []]]                                  ← caso base

Ahora empezamos a resolver:

= [5 | [8]]
= [5, 8]
```

### 5. Mapear (transformar cada elemento)

Por último, se muestra cómo implementar una función `map` que aplica una función dada a cada elemento de una lista.

```elixir
defmodule Listas do
  def main do
    IO.inspect(map([1, 2, 3], fn x -> x * 2 end)) # => [2, 4, 6]
  end

  # Caso base: si la lista está vacía, se devuelve una lista vacía
  def map([], _funcion), do: []

  # Caso recursivo: se aplica la función al head y se sigue con el tail
  def map([head | tail], funcion) do
    [funcion.(head) | map(tail, funcion)]
  end
end

Listas.main()
```

**Traza para `map([1, 2, 3], fn x -> x * 2 end)`:**

> Se usa `f` como abreviación de `fn x -> x * 2 end` para mayor legibilidad.

```
map([1, 2, 3], f)
= [f.(1) | map([2, 3], f)]
= [2 | map([2, 3], f)]
= [2 | [f.(2) | map([3], f)]]
= [2 | [4 | map([3], f)]]
= [2 | [4 | [f.(3) | map([], f)]]]
= [2 | [4 | [6 | map([], f)]]]
= [2 | [4 | [6 | []]]]   ← caso base

Ahora empezamos a resolver:

= [2 | [4 | [6]]]
= [2 | [4, 6]]
= [2, 4, 6]
```

## Recursividad de Cola (Tail Recursion)

La **recursividad de cola** (*tail recursion*) es un tipo de recursión en la que la llamada recursiva es **la última operación** que realiza la función, es decir, su resultado se devuelve directamente, sin realizar ninguna operación adicional con él. Esto permite que Elixir aplique una optimización llamada *tail call optimization* (TCO), que evita que la pila crezca con cada llamada y, con ello, el desbordamiento en recursiones muy profundas.

Lenguajes como **Elixir** y **Erlang** aplican esta optimización de forma automática. Otros lenguajes, como **Python** o **Java**, no la implementan, y en ellos una recursión de miles de niveles termina en *stack overflow* aunque esté escrita de cola.

### ¿Por qué es importante?

Considere la función factorial implementada de dos maneras, una con recursión normal y otra con recursión de cola.

#### Recursión normal (no es de cola)

```elixir
def factorial(0), do: 1
def factorial(n), do: n * factorial(n - 1) # La multiplicación queda pendiente hasta que la llamada retorne
```

Aunque en `n * factorial(n - 1)` la llamada recursiva aparece al final de la expresión, no es la última operación. Cuando `factorial(n - 1)` devuelve su resultado, todavía falta multiplicarlo por `n`, por lo que el marco de cada llamada debe permanecer en la pila, conservando el valor de `n`, hasta recibir ese resultado.

```
Pila crece →

factorial(5)     |  Espera resultado  |
factorial(4)     |  Espera resultado  |
factorial(3)     |  Espera resultado  |
factorial(2)     |  Espera resultado  |
factorial(1)     |  Espera resultado  |
factorial(0) → 1 |  Retorna           |

← Pila se resuelve
```

#### Recursión de cola

```elixir
defmodule Matematicas do
  def main do
    IO.puts(factorial(5)) # => 120
  end

  # Función pública: inicia el acumulador
  def factorial(n), do: factorial_tail(n, 1)

  # Función privada: tail-recursive
  defp factorial_tail(0, acum), do: acum
  defp factorial_tail(n, acum) when n > 0 do
    factorial_tail(n - 1, n * acum) # La llamada es lo último que se hace, no queda nada pendiente
  end
end

Matematicas.main()
```

Se utiliza un parámetro `acum` para mantener los cálculos intermedios y, en el caso base, se devuelve el valor acumulado. Como no queda nada pendiente, Elixir puede aplicar la **optimización de cola**.

**Traza para `factorial(5)`:**

```
factorial(5)               ← llamada pública, inicia acum = 1
→ factorial_tail(5, 1)
→ factorial_tail(4, 5)     (5 * 1 = 5)
→ factorial_tail(3, 20)    (4 * 5 = 20)
→ factorial_tail(2, 60)    (3 * 20 = 60)
→ factorial_tail(1, 120)   (2 * 60 = 120)
→ factorial_tail(0, 120)   (1 * 120 = 120)
→ 120 (caso base)
```

Cada llamada reutiliza el marco de la anterior, así que **no se acumulan llamadas en la pila** y se utiliza un espacio constante, sin importar la profundidad de la recursión. Calcular `factorial(100_000)` con esta versión usa la misma memoria de pila que calcular `factorial(5)`.

## Ejemplos de Tail Recursion

Estos son otros ejemplos escritos con recursividad de cola. Los dos primeros ya se vieron con recursión normal.

### 1. Fibonacci eficiente

La implementación de Fibonacci vista anteriormente recalcula los mismos valores muchas veces, por lo que `fibonacci(50)` requiere más de cuarenta mil millones de llamadas. Con recursividad de cola, cada valor se calcula una sola vez:

```elixir
defmodule Matematicas do
  def main do
    IO.puts(fibonacci(5))  # => 5
    IO.puts(fibonacci(50)) # => 12586269025, al instante
  end

  def fibonacci(n), do: fibonacci(n, 0, 1) # Se inician los dos primeros números de la secuencia

  defp fibonacci(0, a, _b), do: a # Caso base: si n es 0, se devuelve el primer número
  defp fibonacci(n, a, b), do: fibonacci(n - 1, b, a + b) # Se avanza en la secuencia, actualizando los dos últimos números
end

Matematicas.main()
```

**Traza para `fibonacci(5)`:**

En cada paso, `a` toma el valor de `b` y `b` toma el valor de `a + b`.

```
fibonacci(5)                    ← llamada pública, inicia a = 0, b = 1
→ fibonacci(5, 0, 1)
→ fibonacci(4, 1, 1)            (a = 1,   b = 0+1 = 1)
→ fibonacci(3, 1, 2)            (a = 1,   b = 1+1 = 2)
→ fibonacci(2, 2, 3)            (a = 2,   b = 1+2 = 3)
→ fibonacci(1, 3, 5)            (a = 3,   b = 2+3 = 5)
→ fibonacci(0, 5, 8)            (a = 5,   b = 3+5 = 8)
→ 5 (caso base, se devuelve a)
```

En esta implementación, cada valor se calcula una sola vez y se transmite a la siguiente llamada mediante los parámetros `a` y `b`. Para `fibonacci(50)` se realizan alrededor de cincuenta llamadas, en lugar de más de cuarenta mil millones.

### 2. Suma de lista

Un ejemplo de recursividad de cola es la función que suma los elementos de una lista acumulando el resultado en un parámetro adicional:

```elixir
defmodule Listas do
  def main do
    IO.puts(sumar([1, 2, 3])) # => 6
  end

  def sumar(lista), do: sumar(lista, 0)

  defp sumar([], acumulado), do: acumulado
  defp sumar([head | tail], acumulado), do: sumar(tail, head + acumulado)
end

Listas.main()
```

**Traza para `sumar([1, 2, 3])`:**

```
sumar([1, 2, 3])           ← llamada pública, inicia acumulado = 0
→ sumar([2, 3], 1)         (1 + 0 = 1)
→ sumar([3], 3)            (2 + 1 = 3)
→ sumar([], 6)             (3 + 3 = 6)
→ 6 (caso base)
```

### 3. Invertir lista

Para invertir una lista utilizando recursividad de cola, podemos hacer lo siguiente:

```elixir
defmodule Listas do
  def main do
    IO.inspect(invertir([1, 2, 3])) # => [3, 2, 1]
  end

  def invertir(lista), do: invertir_tail(lista, [])

  defp invertir_tail([], acum), do: acum
  defp invertir_tail([head | tail], acum) do
    invertir_tail(tail, [head | acum])
  end
end

Listas.main()
```

**Traza para `invertir([1, 2, 3])`:**

```
invertir([1, 2, 3])               ← llamada pública, inicia acum = []
→ invertir_tail([1, 2, 3], [])
→ invertir_tail([2, 3], [1])      ([1 | []] = [1])
→ invertir_tail([3], [2, 1])      ([2 | [1]] = [2, 1])
→ invertir_tail([], [3, 2, 1])    ([3 | [2, 1]] = [3, 2, 1])
→ [3, 2, 1] (caso base)
```

### El acumulador siempre invierte el orden

Este ejemplo funciona porque **queríamos** invertir la lista, pero conviene entender por qué: al acumular con `[head | acum]`, cada elemento se coloca al inicio del acumulador, de modo que el último en procesarse queda de primero. **Toda función de cola que construye una lista la produce al revés.**

Por eso, cuando el orden original sí importa, el patrón idiomático en Elixir es acumular y luego invertir al final:

```elixir
defmodule Listas do
  def main do
    IO.inspect(duplicar([1, 2, 3])) # => [2, 4, 6]
  end

  def duplicar(lista), do: duplicar(lista, [])

  defp duplicar([], acum), do: Enum.reverse(acum)  # Se restaura el orden original
  defp duplicar([head | tail], acum), do: duplicar(tail, [head * 2 | acum])
end

Listas.main()
```

Sin el `Enum.reverse/1` del caso base, el resultado sería `[6, 4, 2]`. Aunque invertir la lista implica recorrerla una vez más, `Enum.reverse/1` realiza un único recorrido sin agregar marcos a la pila, por lo que la lista se recorre en total dos veces y la pila no crece.

## Recursividad para validar la entrada del usuario

La recursión no solo sirve para **calcular** algo, también para **repetir una acción hasta que se cumpla una condición**. Un caso típico es la lectura de datos por teclado.

Recuerde que en el módulo `Util` de la guía de expresiones lógico-matemáticas, cuando el usuario escribía algo inválido se devolvía un valor por defecto. Esa versión **no resuelve el problema, lo esconde**:

```
Ingrese las horas trabajadas: cuarenta
Error. Se utilizará 0 como valor predeterminado.
El salario de Carlos es: $0.0
```

La solución es que, cuando el parseo falle, la función **se llame a sí misma** con el mismo mensaje. Así no hace falta un valor por defecto y `leer_con_parser/3` pasa a ser `leer_con_parser/2`:

```elixir
def leer(mensaje, :integer), do: leer_con_parser(mensaje, &Integer.parse/1)
def leer(mensaje, :float), do: leer_con_parser(mensaje, &Float.parse/1)

defp leer_con_parser(mensaje, funcion) do
  valor = IO.gets(mensaje)
  |> String.trim()
  |> funcion.()

  case valor do
    # Caso base: el usuario escribió un número válido
    {numero, ""} -> numero

    # Caso recursivo: la entrada no sirve, se vuelve a preguntar
    _ ->
      imprimir_error("Entrada inválida. Debe escribir un número.")
      leer_con_parser(mensaje, funcion)
  end
end
```

La función solo termina cuando el usuario escribe algo que se puede convertir a número:

```
Ingrese las horas trabajadas: cuarenta
Entrada inválida. Debe escribir un número.
Ingrese las horas trabajadas: 40 horas
Entrada inválida. Debe escribir un número.
Ingrese las horas trabajadas: 40
```

El caso base sigue siendo `{numero, ""}`, igual que en el módulo `Util` original. `Integer.parse("40 horas")` devuelve `{40, " horas"}`, que no coincide con ese patrón, así que la entrada se rechaza y se vuelve a preguntar.

Hay dos diferencias frente a los ejemplos anteriores de la guía. Primero, **el caso base no depende de un parámetro que disminuye** sino de lo que escriba el usuario, así que no hay ninguna garantía de que la recursión termine. Segundo, **los argumentos no cambian entre llamadas**, y lo único que cambia es la siguiente línea que escriba el usuario. Como la llamada recursiva es la última expresión, es recursividad de cola y el usuario puede equivocarse mil veces sin desbordar la pila.

## Autosimilaridad: la recursión fuera del código

Una estructura es **autosimilar** cuando está compuesta por partes que tienen la misma forma que la estructura completa. Este es el tipo de problema que resuelve la recursión, y también se presenta fuera de la programación:

1. **Árboles**: Tronco → ramas → ramas más pequeñas → hojas
2. **Ríos**: Río principal → afluentes → arroyos
3. **Pulmones**: Tráquea → bronquios → bronquiolos

Cada uno de estos ejemplos tiene también un **caso base**, un punto donde la subdivisión se detiene. En un árbol son las **hojas**, en un río los **arroyos** más pequeños y en los pulmones los **bronquiolos**. Es exactamente la misma idea que usamos al programar: una parte que se repite (el caso recursivo) y una condición que detiene la repetición (el caso base).

En informática ocurre lo mismo con muchas estructuras de datos:

- **Sistemas de archivos**: una carpeta contiene archivos y otras carpetas, que a su vez contienen más archivos y carpetas.
- **Listas en Elixir**: como vimos, una lista es una cabeza seguida de otra lista (`[head | tail]`), donde la cola es de nuevo una lista.
- **Organigramas**: cada área de una organización se divide en dependencias, que a su vez se dividen en otras más pequeñas.

Por eso la recursión es la forma natural de recorrer este tipo de estructuras, y reconocer el patrón ayuda a identificar cuándo un problema se puede resolver recursivamente.
