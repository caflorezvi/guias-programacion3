## Ejemplo 1: Bienvenida a un videojuego

Un estudio está desarrollando un videojuego llamado Aventura Espacial. El equipo quiere que, al iniciar el juego, se muestre un mensaje de bienvenida al jugador.

El mensaje debe ser: `Bienvenidos al videojuego Aventura Espacial`.

Antes de programar, analice el problema siguiendo los pasos del pensamiento computacional:

1. **Abstracción**: Para este requerimiento solo es relevante el texto del mensaje y el momento en que debe mostrarse. Otros elementos del videojuego, como los gráficos, los niveles o el jugador, no intervienen por ahora.
2. **Descomposición**: El problema tiene dos partes:
   - Obtener el texto del mensaje.
   - Mostrarlo en pantalla.
3. **Identificación de patrones**: Mostrar un texto en pantalla es una tarea que ya se resolvió con el programa "¡Hola, mundo!" de la guía anterior, por lo que puede utilizarse la misma función, `IO.puts/1`, del módulo `IO` (entrada y salida).
4. **Codificación**: Escribimos el código en Elixir para cada una de las partes.

Realice este análisis antes de escribir el código. De esta forma se identifican las partes del problema y las herramientas disponibles para resolver cada una.

### Versión 1

Cree un nuevo archivo llamado `videojuego.exs` dentro de Visual Studio Code y escriba el siguiente código:

```elixir
IO.puts("Bienvenidos al videojuego Aventura Espacial")
```

Ejecute el programa usando el comando `elixir videojuego.exs` en la terminal. Debería ver el mensaje de bienvenida en la salida.

Consideraciones:

- Esta forma es suficiente para probar una instrucción aislada, pero a medida que el programa crece aumenta el número de funciones, y conviene agruparlas en **módulos**. Un módulo reúne bajo un mismo nombre funciones relacionadas, lo que facilita ubicarlas y utilizarlas desde otros archivos.
- Elixir, al igual que otros lenguajes (por ejemplo, Python o JavaScript), no exige una función principal `main()`. Sin embargo, es una buena práctica definir un módulo con una función `main()` que indique el punto de inicio del programa. Así, quien lea el código puede identificar rápidamente dónde comienza la ejecución.

### Versión 2

Modifique el archivo `videojuego.exs` (o créelo si no lo tiene) y escriba el siguiente código:

```elixir
defmodule Videojuego do
  def main do
    IO.puts("Bienvenidos al videojuego Aventura Espacial")
  end
end

Videojuego.main()
```

El módulo `Videojuego` contiene la función `main`, que es la que se invoca para mostrar el mensaje de bienvenida. Para llamarla desde fuera del módulo se escribe el nombre del módulo, un punto y el nombre de la función, igual que en `IO.puts`. Tenga en cuenta que es **necesario invocar** la función `main()` para que el **programa se ejecute**, por lo que se debe incluir la llamada a `Videojuego.main()` al **final del archivo**.

### Versión 3

Modifique el archivo `videojuego.exs` o cree uno nuevo y escriba el siguiente código:

```elixir
defmodule Videojuego do
  def main do
    mensaje = saludar()
    imprimir_mensaje(mensaje)
  end

  defp saludar do
    "Bienvenidos al videojuego Aventura Espacial"
  end

  defp imprimir_mensaje(mensaje) do
    IO.puts(mensaje)
  end
end

Videojuego.main()
```

En este caso, la función `saludar` se define como privada (usando `defp`), lo que significa que solo puede ser llamada desde dentro del módulo `Videojuego`. Además, se ha separado la lógica de impresión en una función diferente (`imprimir_mensaje`). Así cada función tiene una sola tarea, y se puede leer o cambiar una sin tocar la otra.

La función `main` actúa como el punto de entrada del módulo. Primero invoca a `saludar` y luego pasa el texto obtenido a `imprimir_mensaje`.

> ⚠️ **Importante:** `saludar` devuelve la cadena sin usar `return`, porque en Elixir esa palabra clave no existe, a diferencia de Java o C. El valor de la última expresión evaluada en la función es el valor que esta devuelve.

### Versión 4

Ahora se requiere modificar el programa para que el mensaje de bienvenida sea más dinámico y pueda personalizarse. Para ello, se debe modificar la función `saludar` para que reciba un parámetro con el nombre del jugador.

```elixir
defmodule Videojuego do
  def main do
    mensaje = saludar("Carlos")
    imprimir_mensaje(mensaje)
  end

  defp saludar(nombre) do
    "Hola #{nombre}, bienvenido al videojuego Aventura Espacial"
  end

  defp imprimir_mensaje(mensaje) do
    IO.puts(mensaje)
  end
end

Videojuego.main()
```

El nombre que recibe `saludar` se **interpola** en el mensaje con `#{}`, que reemplaza la expresión por su valor dentro de la cadena.

Otra opción para concatenar el mensaje es usar el operador `<>`, así:

```elixir
defp saludar(nombre) do
  "Hola " <> nombre <> ", bienvenido al videojuego Aventura Espacial"
end
```

Pero la interpolación de cadenas con `#{}` es más común y legible en Elixir, especialmente cuando se combinan variables con texto.

#### Argumentos por defecto (`\\`)

Un parámetro puede llevar un valor que se usa cuando quien llama no lo indica. En este programa, `saludar` recibe el nombre con el valor por defecto `"invitado"`, y `main` la llama una vez con nombre y otra sin él:

```elixir
defmodule Videojuego do
  def main do
    imprimir_mensaje(saludar("Carlos"))
    imprimir_mensaje(saludar()) # Sin argumento, se usa el valor por defecto
  end

  defp saludar(nombre \\ "invitado") do
    "Hola #{nombre}, bienvenido al videojuego Aventura Espacial"
  end

  defp imprimir_mensaje(mensaje) do
    IO.puts(mensaje)
  end
end

Videojuego.main()
```

La salida es:

```
Hola Carlos, bienvenido al videojuego Aventura Espacial
Hola invitado, bienvenido al videojuego Aventura Espacial
```

Es una forma habitual de dar un valor inicial sin obligar a escribirlo en cada llamada. Si ninguna llamada usa el valor por defecto, el compilador lo advierte con el mensaje `default values for the optional arguments in the private function saludar/1 are never used`.

### Versión 5

Ahora, se requiere que el nombre del jugador se solicite de forma interactiva en lugar de estar codificado. Para ello, se puede utilizar la función `IO.gets/1` para leer la entrada del jugador.

```elixir
defmodule Videojuego do
  def main do
    nombre = leer_nombre()
    mensaje = saludar(nombre)
    imprimir_mensaje(mensaje)
  end

  defp saludar(nombre) do
    "Hola #{nombre}, bienvenido al videojuego Aventura Espacial"
  end

  defp imprimir_mensaje(mensaje) do
    IO.puts(mensaje)
  end

  defp leer_nombre do
    IO.gets("Por favor, ingrese su nombre: ")
  end
end

Videojuego.main()
```

La función `IO.gets/1` se utiliza para **mostrar un mensaje al jugador y esperar su entrada**, y devuelve lo que el jugador escribió.

Al ejecutar el programa puede observar que después del nombre ingresado, hay un salto de línea adicional. Esto se debe a que `IO.gets/1` incluye el carácter de nueva línea (`\n`) en la entrada capturada. Para solucionar esto, se puede utilizar la función `String.trim/1` para eliminar los espacios en blanco y el salto de línea al final de la cadena.

En el mismo archivo, **reemplace la función `leer_nombre` por esta**. El resto del módulo no cambia.

```elixir
defp leer_nombre do
  nombre = IO.gets("Por favor, ingrese su nombre: ")
  String.trim(nombre)
end
```

### Versión 6 (final)

Para finalizar, podemos simplificar aún más el código utilizando el operador pipe `|>` en la función `main` y `leer_nombre`, así:

```elixir
defmodule Videojuego do
  def main do
    leer_nombre()
    |> saludar()
    |> imprimir_mensaje()
  end

  defp saludar(nombre) do
    "Hola #{nombre}, bienvenido al videojuego Aventura Espacial"
  end

  defp imprimir_mensaje(mensaje) do
    IO.puts(mensaje)
  end

  defp leer_nombre do
    IO.gets("Por favor, ingrese su nombre: ")
    |> String.trim()
  end
end

Videojuego.main()
```

El operador pipe `|>` permite **encadenar funciones**, pasando el resultado de una función como **primer argumento** de la siguiente. Por ejemplo, en `leer_nombre`, el valor que devuelve `IO.gets/1` se pasa directamente a `String.trim/1`. De manera similar, en `main`, el nombre leído se pasa a `saludar` y el mensaje resultante a `imprimir_mensaje`. De esta forma, el código se puede leer en el mismo orden en que se realizan las operaciones, de arriba hacia abajo. Por esta razón, el operador pipe es una de las herramientas más utilizadas en Elixir para expresar transformaciones de datos.

## Ejemplo 2: Validar palíndromos

Se desea crear un script en Elixir que permita validar si una cadena de texto ingresada por el usuario es palíndroma. Un palíndromo es una palabra o frase que se lee igual hacia adelante y hacia atrás, sin tener en cuenta los espacios ni las mayúsculas. Para este ejercicio puede usar el módulo `String` y las siguientes funciones: 

- `String.replace/3` para eliminar los espacios en blanco
- `String.downcase/1` para ignorar mayúsculas y minúsculas.
- `String.reverse/1` para invertir la cadena.

### Versión 1

Cree un archivo llamado `palindroma.exs` y escriba el siguiente código:

```elixir
defmodule Palindroma do

  def main do
    leer_cadena("Ingrese una cadena: ")
    |> es_palindroma?()
    |> generar_mensaje()
    |> imprimir()
  end

  defp es_palindroma?(cadena_texto) do
    cadena_minuscula = String.downcase(cadena_texto) # Convierte a minúsculas toda la cadena
    cadena_sin_espacios = String.replace(cadena_minuscula, " ", "") # Elimina espacios en blanco
    String.reverse(cadena_sin_espacios) == cadena_sin_espacios # Compara la cadena original con la invertida, retorna true o false
  end

  defp imprimir(mensaje) do
    IO.puts(mensaje)
  end

  defp leer_cadena(texto) do
    IO.gets(texto)
    |> String.trim()
  end

  defp generar_mensaje(es_palindroma) do
    if es_palindroma do
      "La cadena es palíndroma"
    else
      "La cadena no es palíndroma"
    end
  end

end

Palindroma.main() # Invoca la función principal para ejecutar el programa
```

Ejecute el programa y verifique su funcionamiento.

La función `generar_mensaje/1` usa la estructura **`if`/`else`** para decidir qué texto retornar según el valor booleano que recibe. Su comportamiento es el mismo que en otros lenguajes (evalúa una condición y ejecuta una de dos ramas), pero con dos diferencias importantes en Elixir:

- El bloque se delimita con `do` y `end`, no con llaves.
- **`if` es una expresión que devuelve un valor**, no una instrucción. Por eso el resultado de la rama que se ejecute es lo que retorna la función, sin necesidad de `return`.

```elixir
mensaje = if 5 > 3, do: "mayor", else: "menor"  # También admite la forma corta
```

> ⚠️ **Importante:** Por buenas prácticas, una función que retorna un valor booleano (`true` o `false`) debe tener un signo de interrogación al final de su nombre, como `es_palindroma?/1`.

### Versión 2

La función `main` ya aprovecha el operador pipe para encadenar las cuatro etapas del programa, pero `es_palindroma?/1` sigue escrita con variables intermedias (`cadena_minuscula`, `cadena_sin_espacios`). Modifíquela para que también use el operador pipe y tenga un enfoque más funcional, así:

```elixir
defp es_palindroma?(cadena) do
  cadena
  |> String.replace(" ", "") # Elimina espacios en blanco
  |> String.downcase() # Convierte toda la cadena a minúsculas
  |> then(fn texto -> texto == String.reverse(texto) end) # Compara el texto con su versión invertida, retorna true o false
end
```

La última etapa usa la función `then/2`. ¿Por qué no basta con el pipe? Porque la comparación necesita la cadena **dos veces**, una a cada lado de `==`. El operador `|>` solo puede pasar el valor como primer argumento de una función, así que no permite usarlo en ambos lados de la comparación.

`then/2` resuelve eso. Recibe el valor que viene por la tubería y se lo entrega a una función anónima, donde ya se puede usar cuantas veces sea necesario.

Analice el código anterior y ejecute el programa para verificar su funcionamiento. Haga su propia versión del programa y pruébelo con diferentes cadenas de texto.

## Documentación

En Elixir existen dos mecanismos para incluir explicaciones en el código, y cada uno tiene un propósito distinto:

- Los **comentarios**, que se escriben con `#`, están dirigidos a quien lee el código. El compilador los ignora.
- La **documentación**, que se escribe con `@moduledoc` y `@doc`, describe qué hace un módulo o una función para quien la va a utilizar. Se almacena junto con el módulo compilado y es el texto que muestra el ayudante `h` en IEx, como ocurre con `h IO.puts`.

Un **comentario de línea** se escribe con el símbolo `#`, y todo lo que sigue en esa línea se ignora. Por ejemplo:

```elixir
def sumar(a, b) do
  a + b # Se suman los valores y se retorna el resultado
end
```

Para **documentar un módulo** se utiliza `@moduledoc`, justo después de `defmodule`. Allí se explica para qué sirve el módulo, y se puede incluir el autor, la fecha de creación o la versión. Por ejemplo:

```elixir
defmodule Calculadora do
  @moduledoc """
  Este módulo realiza operaciones matemáticas.
  - autor: Carlos Andrés Florez V.
  - fecha: Agosto del 2026
  """

  def sumar(a, b) do
    a + b
  end
end
```

Para **documentar una función** se utiliza `@doc`, ubicado justo antes de su definición con `def`. La documentación puede describir qué hace la función, qué parámetros recibe y qué resultado devuelve. Cuando sea útil, también puede incluir un ejemplo de uso. Por ejemplo:

```elixir
defmodule Calculadora do
  @moduledoc """
  Este módulo realiza operaciones matemáticas.
  - autor: Carlos Andrés Florez V.
  - fecha: Agosto del 2026
  """

  @doc """
  Suma dos números.

  ## Ejemplo

      iex> Calculadora.sumar(2, 3)
      5
  """
  def sumar(a, b) do
    a + b
  end
end
```

Las funciones privadas (`defp`) no se documentan con `@doc`, ya que no pueden utilizarse desde fuera del módulo. Si requieren una explicación, se usa un comentario con `#`.

Aplique estas prácticas de documentación en los ejercicios realizados anteriormente.

## Buenas prácticas de nomenclatura

Finalmente, para nombrar funciones y módulos en Elixir, se recomienda seguir las siguientes convenciones:

### 1. Nombres de funciones y variables 

Utilizar nombres en minúsculas y separados por guiones bajos (**snake_case**) para funciones y variables, y nombres en los que cada palabra empieza con mayúscula, sin separadores (**PascalCase**), para módulos.

```elixir
# Bien - Uso de snake_case y PascalCase de manera correcta
defmodule MiModuloEjemplo do
  def funcion_ejemplo do
    # código aquí
  end
end

# Mal - Uso incorrecto de mayúsculas y minúsculas (este código ni siquiera compila)
defmodule mimoduloejemplo do
  def FuncionEjemplo do
    # código aquí
  end
end
```

### 2. Nombres descriptivos

Los nombres deben ser **descriptivos y reflejar la funcionalidad del código**. Por la misma razón conviene evitar abreviaturas y siglas que no sean ampliamente conocidas, ya que el código lo leerán otras personas, o uno mismo meses después.

```elixir
# Bien - El nombre describe claramente la función
def calcular_precio_con_descuento(precio, porcentaje_descuento)
def validar_correo_electronico(correo)

# Mal - Nombre ambiguo y abreviaturas poco claras
def calc(p, d)
def val_email(e)
```

### 3. Consistencia en la nomenclatura

Mantener la **consistencia en la nomenclatura** a lo largo del proyecto. Por ejemplo, si las funciones que consultan un dato comienzan con `obtener_`, todas las funciones de ese tipo deberían seguir la misma convención, de modo que su nombre sea predecible. Lo mismo aplica al idioma. En la industria lo habitual es el inglés, y en un contexto académico el español es aceptable, pero no se recomienda mezclar ambos.

```elixir
# Bien - Nomenclatura consistente
def obtener_usuario(id)
def obtener_producto(id)
def obtener_pedido(id)

# Mal - Inconsistente
def obtener_usuario(id)
def get_producto(id)      # Mezcla español e inglés
def traer_pedido(id)      # Usa verbo diferente
```

### 4. Delegar responsabilidades a funciones pequeñas

Se recomienda que la función `main` se limite a invocar funciones pequeñas, cada una con una única responsabilidad, como en la Versión 6 del videojuego, donde `main` lee el nombre, construye el saludo y lo imprime. De esta forma, `main` describe el flujo general del programa, y cada paso puede modificarse sin afectar a los demás. Cada una de estas funciones corresponde a una de las partes identificadas en la fase de descomposición.

Realice los siguientes ejercicios para practicar los conceptos básicos de Elixir, aplicando el pensamiento computacional en cada uno.

### Ejercicio 1

Una empresa de envíos ha desarrollado un sistema para registrar paquetes. El encargado desea que, al iniciar el sistema, se solicite al usuario su nombre, el nombre del destinatario y la dirección de entrega.
Con esa información, el sistema debe mostrar un único mensaje concatenado que confirme el registro, por ejemplo:

`"El paquete a nombre de Carlos quedó registrado para ser entregado a Pedro en la dirección Calle 123, Bogotá."`

### Ejercicio 2

La oficina de admisiones de la universidad necesita un programa que genere el **correo institucional** de un estudiante a partir de su nombre y su apellido.

El programa debe solicitar al usuario su nombre y su apellido por separado, y luego construir el correo siguiendo estas reglas:

- Todo en minúsculas.
- Sin espacios en blanco al inicio o al final.
- Con el formato `nombre.apellido@uniquindio.edu.co`.

Por ejemplo, si el usuario ingresa `Carlos` y `Florez`, el programa debe mostrar:

`Su correo institucional es: carlos.florez@uniquindio.edu.co`

Para resolverlo puede usar las siguientes funciones:

- `String.trim/1` para eliminar los espacios en blanco al inicio y al final.
- `String.downcase/1` para convertir el texto a minúsculas.

Tenga en cuenta lo siguiente:

- Organice la solución en un módulo con una función `main` que delegue en funciones pequeñas (por ejemplo, una para leer los datos, otra para construir el correo y otra para imprimir el mensaje).
- Use el operador pipe `|>` para encadenar las transformaciones de las cadenas.
- Aplique las buenas prácticas de documentación y nomenclatura vistas en esta guía.

### Ejercicio 3

Una red social desea validar de forma sencilla los nombres de usuario que eligen las personas al registrarse. Por ahora, la única regla es que el nombre de usuario **debe tener al menos 5 caracteres** (sin contar los espacios al inicio o al final).

El programa debe:

1. Solicitar al usuario el nombre de usuario que desea registrar.
2. Eliminar los espacios en blanco al inicio y al final.
3. Calcular su longitud usando la función `String.length/1`.
4. Mostrar un mensaje según el resultado:
   - Si tiene 5 caracteres o más: `"Nombre de usuario válido"`.
   - Si tiene menos de 5 caracteres: `"Nombre de usuario muy corto, debe tener al menos 5 caracteres"`.

Tenga en cuenta lo siguiente:

- Use la estructura `if`/`else` para decidir el mensaje a mostrar.
- Separe la lógica en funciones pequeñas y documente el módulo.

### Ejercicio 4

Un programa útil **debe** tener efectos secundarios, como escribir en la consola, pero conviene **minimizarlos y aislarlos**. La siguiente función no cumple ese principio, porque mezcla el cálculo con la escritura en consola:

```elixir
def convertir_temperatura(celsius) do
  resultado = celsius * 9 / 5 + 32
  IO.puts("La temperatura en Fahrenheit es: #{resultado}")
end
```

Reescríbala dentro de un módulo, separándola en **dos funciones**: una completamente pura, que solo haga la conversión y devuelva el resultado, y otra que se encargue únicamente de imprimirlo. Agregue una función `main` que las coordine.

Responda: ¿cuál de las dos funciones podría probar automáticamente sin necesidad de leer la consola? Relacione su respuesta con la buena práctica de **delegar responsabilidades a funciones pequeñas** vista en esta guía.

### Ejercicio 5

En una tienda, el precio que paga un cliente depende del descuento que le corresponde según su tipo. En lugar de escribir una función distinta para cada tipo de cliente, se puede escribir **una función que fabrique esas funciones**, siguiendo el patrón de **funciones que devuelven funciones**.

Escriba un módulo con una función `crear_descuento/1` que reciba un **porcentaje de descuento** y devuelva una **función anónima**. Esa función anónima recibirá un precio y deberá retornar el **precio final, ya con el descuento aplicado**.

Al usarla, debe comportarse así:

```elixir
descuento_estudiante = Tienda.crear_descuento(20)   # Fabrica una función de 20 % de descuento
descuento_empleado = Tienda.crear_descuento(35)     # Fabrica una función de 35 % de descuento

descuento_estudiante.(50000)  # => 40000.0
descuento_empleado.(50000)    # => 32500.0
```

Tenga en cuenta lo siguiente:

- El **punto** en `descuento_estudiante.(50000)` es obligatorio: así se invocan las funciones anónimas en Elixir.
- El resultado es un número decimal (`40000.0`) porque el operador `/` en Elixir siempre devuelve un valor de tipo `float`.

Responda: cuando se ejecuta `descuento_estudiante.(50000)`, la función `crear_descuento(20)` ya terminó hace rato. ¿De dónde obtiene entonces la función anónima el valor `20`? Relacione su respuesta con el concepto de **clausura** y con la inmutabilidad de los datos.
