## Tipos de datos y operadores

En Elixir existen diferentes tipos de datos, como `integer`, `float`, `boolean`, `atom`, `string`, `list` y `tuple`, entre otros. Cada tipo de dato tiene características particulares y puede utilizarse con diferentes funciones y operadores. Conocer estas operaciones permite trabajar y transformar los datos de acuerdo con las necesidades del programa.

Los operadores lógicos, matemáticos y de comparación se agrupan así:

- Operadores lógicos: `and`, `or`, `not` 
- Operadores matemáticos: `+`, `-`, `*`, `/`
- Operadores de comparación: `==`, `!=`, `>`, `<`, `>=`, `<=`, `===`, `!==`

También existen funciones matemáticas como:

- `div/2`, calcula la división entera.
- `rem/2`, calcula el residuo de una división.
- `abs/1`, devuelve el valor absoluto de un número.
- `round/1`, redondea un número al entero más cercano.
- `min/2` y `max/2`, devuelven el valor mínimo y máximo entre dos números, respectivamente.
- `trunc/1`, devuelve la parte entera de un número decimal.

Por ejemplo:

```elixir
div(7, 2)   # => 3   (división entera)
rem(7, 2)   # => 1   (residuo de la división)
abs(-4)     # => 4
round(3.6)  # => 4
min(3, 5)   # => 3
max(3, 5)   # => 5
trunc(3.7)  # => 3
```

Para más información sobre tipos de datos, operadores y funciones básicas, puede acceder a [https://hexdocs.pm/elixir/basic-types.html](https://hexdocs.pm/elixir/basic-types.html).

## Átomos y tuplas

Los tipos de datos `atom` y `tuple` son estructuras de datos importantes en Elixir. Un `atom` es un valor constante que se utiliza comúnmente como identificador o etiqueta. Por ejemplo, `:ok`, `:error` y `:user` son átomos. Por otro lado, una `tuple` es una colección ordenada de elementos que puede contener diferentes tipos de datos. Las tuplas se definen utilizando llaves `{}` y son útiles para agrupar valores relacionados.

Para más información sobre átomos y tuplas, puede consultar [documentación de átomos](https://hexdocs.pm/elixir/Atom.html) y [documentación de tuplas](https://hexdocs.pm/elixir/Tuple.html).

## Ejemplo 1: Descuentos por compra

Una empresa está haciendo una campaña para promocionar un nuevo producto. Por lo tanto, se está dando un porcentaje de descuento al valor total de la compra de los clientes, el cual varía según el monto de la compra. 

El programa debe solicitar al usuario el monto de la compra y luego aplicar el descuento correspondiente. Los rangos de descuento son los siguientes:

- Si el monto es mayor a **\$50.000** y menor o igual a **\$100.000**, el descuento es del 5%.
- Si el monto es mayor a **\$100.000** y menor o igual a **\$500.000**, el descuento es del 10%.
- Si el monto es mayor a **\$500.000**, el descuento es del 15%.

Se requiere implementar un programa que calcule el precio final después de aplicar el descuento correspondiente e imprima un mensaje con el resultado.

### Versión 1

```elixir
defmodule Descuento do

  def main do
    precio = leer_precio()
    descuento = obtener_descuento(precio)
    precio_final = calcular_descuento(precio, descuento)

    generar_mensaje(precio, descuento, precio_final)
    |> IO.puts()
  end

  defp leer_precio do
    IO.gets("Ingrese el valor de la compra: ")
    |> String.trim()
    |> String.to_float() # Convierte la cadena a un número decimal
  end

  defp obtener_descuento(precio) do
    if precio <= 50000 do
      0
    else
      if precio <= 100000 do
        0.05
      else
        if precio <= 500000 do
          0.1
        else
          0.15
        end
      end
    end
  end

  defp calcular_descuento(precio, descuento), do: precio - (precio * descuento)

  defp generar_mensaje(precio, descuento, precio_final) do
    "El precio original es: #{precio}, el descuento aplicado es: #{descuento * 100}%, y el precio final es: #{precio_final}"
  end

end

Descuento.main()
```

Guarde el archivo como `descuento.exs` y ejecútelo con `elixir descuento.exs`. La sesión se ve así, donde lo que aparece después de los dos puntos es lo que usted escribe:

```
Ingrese el valor de la compra: 120000.0
El precio original es: 1.2e5, el descuento aplicado es: 10.0%, y el precio final es: 1.08e5
```

Pruebe con valores de cada rango para comprobar que los cuatro descuentos funcionan:

```
Ingrese el valor de la compra: 30000.0
El precio original es: 3.0e4, el descuento aplicado es: 0%, y el precio final es: 3.0e4
```

```
Ingrese el valor de la compra: 60000.0
El precio original es: 6.0e4, el descuento aplicado es: 5.0%, y el precio final es: 5.7e4
```

> ⚠️ **Importante:** `String.to_float/1` exige que la cadena incluya los decimales. Si el usuario escribe `75000`, el programa **falla** con un `ArgumentError`; debe escribir `75000.0`.

Al ejecutarlo notará también que los valores grandes se imprimen en **notación científica**: al ingresar `200000.0` el mensaje muestra `2.0e5` en lugar de `200000.0`. Así representa Elixir los números decimales grandes. Por ahora no afecta el resultado del cálculo; en un ejemplo posterior se verá cómo darles formato.

Aunque el código funciona correctamente, presenta múltiples estructuras `if` anidadas que reducen la legibilidad y dificultan el mantenimiento. Elixir ofrece otras formas de evaluar varias condiciones sin anidarlas, como se verá en las siguientes versiones.
 
### Versión 2

En esta nueva versión se modifica la función `obtener_descuento/1` para utilizar `cond`.

```elixir
defp obtener_descuento(precio) do
  cond do
    precio <= 50000 -> 0
    precio <= 100000 -> 0.05
    precio <= 500000 -> 0.1
    true -> 0.15
  end
end
```

Con `cond`, las condiciones quedan una debajo de otra, sin anidar.

La última condición `true` actúa como un caso por defecto, si ninguna de las condiciones anteriores se cumple, se aplica un descuento del 15%.

Ejecute el programa con los mismos valores de la Versión 1 y compruebe que **la salida es idéntica**. Cambió la forma de escribir la decisión, no el resultado.

### Versión 3

En esta nueva versión se modifica la función `obtener_descuento/1` para utilizar `guard`.

```elixir
defp obtener_descuento(precio) when precio > 50000 and precio <= 100000, do: 0.05
defp obtener_descuento(precio) when precio > 100000 and precio <= 500000, do: 0.1
defp obtener_descuento(precio) when precio > 500000, do: 0.15
defp obtener_descuento(_), do: 0
```

Al utilizar `guard`, la función `obtener_descuento/1` se divide en múltiples cláusulas, cada una de las cuales maneja un caso específico. El último caso maneja cualquier valor (`_`) que no cumpla con los criterios anteriores y devuelve un descuento del 0%.

Para más información puede leer acerca de [cond](https://hexdocs.pm/elixir/case-cond-and-if.html#cond) y [guard](https://hexdocs.pm/elixir/patterns-and-guards.html#guards) en la documentación oficial de Elixir, allí puede profundizar en el uso de estas estructuras de control.

Con estas tres versiones se resolvió el problema de decidir entre varios rangos.

## Ejemplo 2: Cálculo del salario

La oficina de tesorería de una empresa requiere un programa que calcule el salario de un empleado, considerando las horas trabajadas y el valor establecido por hora. El programa debe solicitar el nombre del empleado, la cantidad de horas laboradas y el valor por hora, para luego obtener el salario correspondiente e imprimirlo.

### Versión 1

```elixir
defmodule Salario do

  def main do
    nombre = leer_nombre()
    horas_trabajadas = leer_horas_trabajadas()
    valor_por_hora = leer_valor_por_hora()

    salario = calcular_salario(horas_trabajadas, valor_por_hora)
    imprimir_mensaje(nombre, salario)
  end

  defp leer_nombre do
    IO.gets("Ingrese el nombre del empleado: ") 
    |> String.trim()
  end

  defp leer_horas_trabajadas do
    IO.gets("Ingrese las horas trabajadas: ") 
    |> String.trim() 
    |> String.to_integer() # Convierte la cadena a un número entero
  end

  defp leer_valor_por_hora do
    IO.gets("Ingrese el valor por hora: ") 
    |> String.trim() 
    |> String.to_float() # Convierte la cadena a un número decimal
  end

  defp calcular_salario(horas_trabajadas, valor_por_hora), do: horas_trabajadas * valor_por_hora

  defp imprimir_mensaje(nombre, salario) do
    IO.puts("El salario de #{nombre} es: $#{salario}")
  end
end

Salario.main()
```

Al ejecutarlo:

```
Ingrese el nombre del empleado: Ana
Ingrese las horas trabajadas: 45
Ingrese el valor por hora: 20000.0
El salario de Ana es: $9.0e5
```

El valor por hora se escribe con decimales (`20000.0`). Si escribe `20000` el programa se cae, que es el problema que este ejemplo va a resolver:

```
Ingrese el valor por hora: 20000
** (ArgumentError) errors were found at the given arguments:

  * 1st argument: not a textual representation of a float

    :erlang.binary_to_float("20000")
```

`String.to_integer/1` y `String.to_float/1` lanzan una excepción cuando la cadena no representa un número válido. Una forma de manejar ese caso es usarlas dentro de un bloque `try`/`rescue`.

### Versión 2

Usando `try`/`rescue` la función `leer_horas_trabajadas/0` quedaría de la siguiente manera:

```elixir
defp leer_horas_trabajadas do
  entrada = IO.gets("Ingrese las horas trabajadas: ") 
  |> String.trim()

  try do # Intenta convertir la entrada a un número entero
    String.to_integer(entrada)
  rescue # Si ocurre un ArgumentError, se imprime un mensaje de error y se devuelve 0
    ArgumentError ->
      IO.puts("Horas trabajadas inválidas. Se utilizará 0 como valor predeterminado.")
      0
  end
end
```

Se asume que algo similar a lo que se hizo con `leer_horas_trabajadas/0` se hará con `leer_valor_por_hora/0`. 

Aunque esta implementación es mejor, en Elixir **se prefiere utilizar un enfoque más funcional y menos imperativo**. En lugar de usar `try`/`rescue`, se pueden utilizar las funciones `Integer.parse/1` y `Float.parse/1` para manejar la entrada del usuario sin que el programa se detenga.

### Versión 3

En esta versión, las dos funciones de lectura usan `Integer.parse/1` y `Float.parse/1`, que no lanzan excepciones:

```elixir

defp leer_horas_trabajadas do
  horas = IO.gets("Ingrese las horas trabajadas: ") 
  |> String.trim() 
  |> Integer.parse() # Devuelve una tupla o :error

  case horas do # Coincidencia de patrones
    {numero, ""} -> numero # La entrada es solo un número, no sobró texto
    _ -> # Cualquier otro caso: :error, o un número seguido de texto como "45abc"
      imprimir_error("Horas trabajadas inválidas. Se utilizará 0 como valor predeterminado.")
      0 # Se devuelve 0 como valor predeterminado
  end
end

defp leer_valor_por_hora do
  valor = IO.gets("Ingrese el valor por hora: ") 
  |> String.trim() 
  |> Float.parse()

  case valor do
    {numero, ""} -> numero
    _ ->
      imprimir_error("Valor por hora inválido. Se utilizará 0.0 como valor predeterminado.")
      0.0 # Se devuelve 0.0 como valor predeterminado porque es un número decimal
  end
end

defp imprimir_error(mensaje) do
  IO.puts(:standard_error, mensaje) # Imprime el mensaje de error en la salida estándar de errores (por defecto es la terminal)
end
```

`Integer.parse/1` y `Float.parse/1` retornan una tupla `{numero, resto}` con el número convertido y el texto que sobró, o el átomo `:error` si la cadena no comienza con un número:

```elixir
Integer.parse("123abc")
# => {123, "abc"}

Integer.parse("42")
# => {42, ""}

Integer.parse("abc")
# => :error

Float.parse("3.14xyz")
# => {3.14, "xyz"}
```

Para distinguir esos resultados se usa `case`, que aplica la **coincidencia de patrones**, es decir, verifica la forma de un dato y al mismo tiempo extrae información de él. El `case` prueba los patrones en orden. `{numero, ""}` solo coincide con una tupla cuyo segundo elemento es la cadena vacía, y al coincidir enlaza el número a la variable `numero`. `_` coincide con cualquier valor, así que recoge todo lo que no coincidió con el patrón anterior.

¿Por qué no usar `{numero, _}`, que ignora el resto? Porque entonces `"45abc"` se aceptaría como 45, y `"20000,5"` (con coma en lugar de punto) como `20000.0`, sin que el usuario se enterara de que parte de lo que escribió se descartó. Con `{numero, ""}` solo se acepta una entrada que sea **completamente** un número.

**El operador `=` es coincidencia, no asignación.** En Elixir, `=` no asigna como en otros lenguajes: *hace coincidir* el patrón de la izquierda con el valor de la derecha. Si la variable de la izquierda no tiene valor, se *enlaza* a él; si las formas no coinciden, ocurre un `MatchError`:

```elixir
x = 1                           # x se enlaza a 1
{numero, resto} = {123, "abc"}  # numero = 123, resto = "abc"
{a, b} = {1, 2, 3}              # ** (MatchError): las formas no coinciden
```

El `case` anterior usa esta misma idea: compara el valor contra cada patrón hasta encontrar el que coincide.

Ejecute ahora el programa y escriba algo que no sea un número. Compare el resultado con el `ArgumentError` de la Versión 1:

```
Ingrese el nombre del empleado: Carlos
Ingrese las horas trabajadas: 45
Ingrese el valor por hora: abc
Valor por hora inválido. Se utilizará 0.0 como valor predeterminado.
El salario de Carlos es: $0.0
```

El programa ya no se cae. Avisa del problema, usa el valor por defecto y sigue adelante, que era el objetivo de este ejemplo.

Para más información puede leer acerca del [Módulo String](https://hexdocs.pm/elixir/String.html), [Módulo Integer](https://hexdocs.pm/elixir/Integer.html) y [Módulo Float](https://hexdocs.pm/elixir/Float.html). Adicionalmente, se recomienda revisar [esta documentación](https://hexdocs.pm/elixir/case-cond-and-if.html#case) para profundizar en el uso de la estructura `case` y [esta documentación](https://hexdocs.pm/elixir/pattern-matching.html) para entender la **coincidencia de patrones**.

### Versión 4

Para mejorar la organización del código, se puede **crear un módulo separado** para manejar las operaciones de entrada/salida. Esto permite que el módulo `Salario` se enfoque en la lógica de negocio y delegue las operaciones de entrada/salida a otro módulo.

```elixir
defmodule Salario do
  @moduledoc """
  Módulo que contiene la lógica para calcular el salario de un empleado.
  """

  def main do
    nombre = "Ingrese el nombre del empleado: "
    |> Util.leer(:string)

    horas_trabajadas = "Ingrese las horas trabajadas: "
    |> Util.leer(:integer)

    valor_por_hora = "Ingrese el valor por hora: "
    |> Util.leer(:float)

    salario = calcular_salario(horas_trabajadas, valor_por_hora)

    generar_mensaje(nombre, salario)
    |> Util.imprimir_mensaje
  end

  defp calcular_salario(horas_trabajadas, valor_por_hora), do: horas_trabajadas * valor_por_hora

  defp generar_mensaje(nombre, salario) do
    "El salario de #{nombre} es: $#{salario}"
  end

end

defmodule Util do
  @moduledoc """
  Módulo de utilidades para manejo de entrada/salida. Este módulo puede ser reutilizado 
  en otros programas para leer diferentes tipos de datos y manejar errores de entrada de manera consistente.
  """

  def leer(mensaje, :string) do
    IO.gets(mensaje)
    |> String.trim()
  end

  def leer(mensaje, :integer) do
    valor = IO.gets(mensaje)
    |> String.trim()
    |> Integer.parse()

    case valor do
      {numero, ""} -> numero
      _ ->
        imprimir_error("Error. Se utilizará 0 como valor predeterminado.")
        0
    end
  end

  def leer(mensaje, :float) do
    valor = IO.gets(mensaje)
    |> String.trim()
    |> Float.parse()

    case valor do
      {numero, ""} -> numero
      _ ->
        imprimir_error("Error. Se utilizará 0.0 como valor predeterminado.")
        0.0 # Se devuelve 0.0 para conservar el tipo flotante
    end
  end

  def imprimir_error(mensaje) do
    IO.puts(:standard_error, mensaje)
  end

  def imprimir_mensaje(mensaje) do
    IO.puts(mensaje)
  end

end

Salario.main()
```

Ahora las funciones del módulo `Util` gestionan la entrada y salida de datos y pueden reutilizarse fácilmente desde otros módulos. Además, se emplea un **átomo** para indicar el tipo de dato a leer (`:string`, `:integer` o `:float`), y Elixir elige la cláusula de `leer/2` correspondiente gracias a la **coincidencia de patrones**.

### Versión 5

Finalmente, se modificará el módulo `Util` para que las funciones de lectura de enteros y flotantes utilicen una función auxiliar encargada de capturar el valor, realizar su *parseo* y manejar posibles errores. Con este cambio se **reduce la duplicación de código**, ya que las funciones `leer(mensaje, :integer)` y `leer(mensaje, :float)` tenían implementaciones prácticamente idénticas.

```elixir
defmodule Util do

  def leer(mensaje, :string) do
    IO.gets(mensaje)
    |> String.trim()
  end

  def leer(mensaje, :integer) do
    leer_con_parser(mensaje, &Integer.parse/1, 0) # Se pasa la función de parseo y el valor por defecto
  end

  def leer(mensaje, :float) do
    leer_con_parser(mensaje, &Float.parse/1, 0.0) # Para flotantes el valor por defecto es 0.0
  end

  defp leer_con_parser(mensaje, funcion, valor_defecto) do
    valor = IO.gets(mensaje)
    |> String.trim()
    |> funcion.() # Se ejecuta la función de parseo

    case valor do
      {numero, ""} -> numero
      _ ->
        imprimir_error("Error. Se utilizará #{valor_defecto} como valor predeterminado.")
        valor_defecto
    end
  end

  def imprimir_error(mensaje) do
    IO.puts(:standard_error, mensaje)
  end

  def imprimir_mensaje(mensaje) do
    IO.puts(mensaje)
  end

end
```

`&Integer.parse/1` pasa la función `Integer.parse/1` como argumento, sin ejecutarla. Dentro de `leer_con_parser/3` se ejecuta con el operador punto, `funcion.(valor)`. Otra alternativa es pasar la función así:

```elixir
def leer(mensaje, :integer) do
  leer_con_parser(mensaje, fn valor -> Integer.parse(valor) end, 0)
end
```

La segunda forma usa una **función anónima** (lambda), que recibe el valor y llama a `Integer.parse/1` con él. Ambas hacen lo mismo, así que use la que le resulte más legible.

## Ejemplo 3: Nota definitiva de un curso

Un estudiante necesita un programa que le ayude a calcular la nota definitiva de dos cursos, cada curso tiene 4 notas parciales. El primer curso calcula la nota definitiva como un promedio aritmético, mientras que el segundo curso lo hace mediante un promedio ponderado usando los porcentajes de 15%, 30%, 35% y 20% respectivamente. Además, el programa debe indicar si el estudiante aprueba o no.

### Versión 1

```elixir
defmodule Notas do

  def main do
    n1 = Util.leer("Ingrese la nota 1: ", :float)
    n2 = Util.leer("Ingrese la nota 2: ", :float)
    n3 = Util.leer("Ingrese la nota 3: ", :float)
    n4 = Util.leer("Ingrese la nota 4: ", :float)

    nota_final = calcular_nota_curso_1(n1, n2, n3, n4)
    es_aprobado = aprobado?(nota_final)

    generar_mensaje(es_aprobado, nota_final)
    |> Util.imprimir_mensaje()

  end

  defp calcular_nota_curso_1(n1, n2, n3, n4), do: (n1 + n2 + n3 + n4) / 4

  defp calcular_nota_curso_2(n1, n2, n3, n4), do: n1 * 0.15 + n2 * 0.30 + n3 * 0.35 + n4 * 0.20

  defp aprobado?(nota), do: nota >= 3.0

  defp generar_mensaje(es_aprobado, nota) do
    if es_aprobado do
      "El estudiante aprobó el curso con una nota de #{nota}."
    else
      "El estudiante no aprobó el curso con una nota de #{nota}."
    end
  end

end

Notas.main()
```

Con cuatro notas que promedian por encima de 3.0:

```
Ingrese la nota 1: 4.0
Ingrese la nota 2: 4.5
Ingrese la nota 3: 3.0
Ingrese la nota 4: 3.5
El estudiante aprobó el curso con una nota de 3.75.
```

Y con notas más bajas:

```
Ingrese la nota 1: 2.0
Ingrese la nota 2: 1.5
Ingrese la nota 3: 3.0
Ingrese la nota 4: 2.5
El estudiante no aprobó el curso con una nota de 2.25.
```

Las funciones `calcular_nota_curso_1/4`, `calcular_nota_curso_2/4` y `aprobado?/1` son lo suficientemente simples como para aprovechar la sintaxis `do:` de una sola línea. El `?` final de `aprobado?/1` sigue la convención de Elixir para las funciones que devuelven `true` o `false`.

> ⚠️ **Nota:** La función `calcular_nota_curso_2/4` se define desde ahora porque se utilizará en la Versión 4, pero como todavía no se invoca, Elixir mostrará al ejecutar la advertencia `function calcular_nota_curso_2/4 is unused`. Puede ignorarla por el momento.

### Versión 2

Para esta versión se usa la **coincidencia de patrones** para simplificar la generación de mensajes.

En el archivo de la Versión 1, **borre por completo la función `generar_mensaje/2`** (la que usa `if`/`else`) y escriba en su lugar estas dos líneas. El resto del módulo `Notas` no cambia.

```elixir
defp generar_mensaje(true, nota), do: "El estudiante aprobó el curso con una nota de #{nota}."
defp generar_mensaje(false, nota), do: "El estudiante no aprobó el curso con una nota de #{nota}."
```

Ahora hay dos cláusulas de `generar_mensaje/2`, y esto también es coincidencia de patrones. Además de enlazar variables, los patrones pueden comparar contra **valores concretos**, aquí `true` y `false`. Elixir prueba las cláusulas de arriba hacia abajo y ejecuta la primera que coincide.

### Versión 3 (opcional)

En ciertos casos, los números pueden tener muchos decimales, lo que puede dificultar la lectura del resultado. Para mejorar la presentación de la nota final, se puede utilizar la función `Float.round/2` para redondear el resultado a un número específico de decimales. Por ejemplo, para redondear a dos decimales, se puede modificar la función `calcular_nota_curso_1/4` de la siguiente manera:

```elixir
defp calcular_nota_curso_1(n1, n2, n3, n4) do
  nota = (n1 + n2 + n3 + n4) / 4
  Float.round(nota, 2) # Redondea la nota a dos decimales
end
```

La diferencia entre `Float.round/2` y `:erlang.float_to_binary/2` es que `Float.round/2` devuelve un número de punto flotante redondeado, mientras que `:erlang.float_to_binary/2` devuelve una cadena que representa el número en un formato específico.
