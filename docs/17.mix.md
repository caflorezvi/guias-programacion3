# Mix


Mix es la herramienta oficial de construcción y gestión de proyectos para Elixir. Proporciona utilidades para desarrollo, compilación, pruebas y gestión de dependencias. Mix es el equivalente a herramientas como `npm` en JavaScript, `pip` en Python o `Maven` en Java, pero está específicamente diseñado para el ecosistema Elixir.

## ¿Por qué usar Mix?

Los proyectos con varios archivos y módulos se benefician de Mix por estas razones:

- **Organización del código**: Mix proporciona una estructura estándar para proyectos Elixir, lo que facilita la navegación, el mantenimiento del código y el trabajo en equipo.
- **Gestión de dependencias**: Mix facilita la inclusión y gestión de bibliotecas externas, lo que permite aprovechar el ecosistema de Elixir.
- **Automatización de tareas**: Mix permite definir y ejecutar tareas personalizadas, como compilación, pruebas y despliegue.
- **Integración con herramientas de Elixir**: Mix se integra perfectamente con otras herramientas del ecosistema Elixir, como ExUnit para pruebas y Hex para la gestión de paquetes.

Para más información, puede consultar la [documentación oficial de Mix](https://hexdocs.pm/mix/Mix.html).

## Estructura de un proyecto Mix

Un proyecto Mix típico tiene la siguiente estructura de directorios:

```
my_app/
├── _build/              # Archivos compilados (generado)
├── config/              # Archivos de configuración (opcional)
│   └── config.exs       # Archivo de configuración principal
├── lib/                 # Código fuente de la aplicación
│   └── my_app.ex        # Módulo principal
├── test/                # Pruebas unitarias
│   ├── test_helper.exs  # Configuración de pruebas
│   └── my_app_test.exs  # Pruebas del módulo principal
├── .gitignore           # Archivos ignorados por Git
├── mix.exs              # Archivo de configuración del proyecto
└── README.md            # Documentación del proyecto
``` 

### Comandos comunes de Mix

Con los siguientes comandos podemos gestionar y trabajar con proyectos Mix:

```bash
mix new my_app          # Crear un nuevo proyecto Mix
cd my_app
mix compile             # Compilar el proyecto
mix test                # Ejecutar pruebas
mix deps.get            # Obtener dependencias (descargarlas)
mix run                 # Ejecutar la aplicación
mix help                # Mostrar ayuda sobre comandos Mix
```

### Creación y compilación de un proyecto Mix

En su terminal, cree un nuevo proyecto Mix con `mix new my_app`, abra el proyecto en Visual Studio Code o su editor de texto preferido. Revise la estructura del proyecto.

## Archivo `mix.exs`

El archivo `mix.exs` es el archivo de configuración principal de un proyecto Mix. Aquí es donde se definen las dependencias, la versión del proyecto, el nombre del módulo principal, entre otros. Un ejemplo básico de un archivo `mix.exs` podría ser:

```elixir
defmodule MyApp.MixProject do
  use Mix.Project # Indica que este módulo es un proyecto Mix

  # Configuración del proyecto
  def project do 
    [
      app: :my_app,
      version: "0.1.0",
      elixir: "~> 1.18",
      start_permanent: Mix.env() == :prod,
      deps: deps()
    ]
  end

  # Configuración de la aplicación
  def application do
    [
        extra_applications: [:logger]
    ]
  end

  # Definición de dependencias externas
  defp deps do
    []
  end
end
```

## Módulo principal y aplicaciones adicionales

Se recomienda usar el módulo `Application` para definir el punto de entrada de la aplicación. Para esto, debe modificar el archivo `lib/my_app.ex` para que se vea así:

```elixir
defmodule MyApp do
  use Application # Indica que este módulo es una aplicación OTP
    
    # Application necesita una función start/2. Esta función es el punto de entrada de la aplicación.
    def start(_type, _args) do
        IO.puts("Hello, Mix!")
        {:ok, self()}
    end
end
```

`Application` es parte de OTP y está pensado para aplicaciones que arrancan procesos supervisados, como se verá más adelante en esta guía.

A su vez, en el archivo `mix.exs`, se debe especificar el módulo principal de la aplicación, que es el punto de entrada cuando se ejecuta la aplicación. Para esto, modifique la función `application` en `mix.exs` para que incluya el módulo principal:

```elixir
def application do
  [
    mod: {MyApp, []}, # Módulo principal de la aplicación
    extra_applications: [:logger]
  ]
end
```

`:logger` es la biblioteca estándar de Elixir para registrar mensajes (*logging*), y `extra_applications` indica que el proyecto la usa.

## Ejecución de la aplicación

Ubique el directorio del proyecto y compilelo con:

```bash
mix compile
```

Luego, ejecute la aplicación con:

```bash
mix run
``` 

Debería ver el mensaje `Hello, Mix!` en la consola.

## Árbol de supervisión en una aplicación OTP

En las guías de **OTP** y **Supervisores** vimos `GenServer` y supervisores ejecutados desde scripts `.exs`. En un proyecto Mix real, lo habitual es que la función `start/2` de la `Application` **inicie un supervisor raíz**, que a su vez arranca y vigila los procesos de la aplicación. Así, todo el sistema queda supervisado desde el arranque.

Por ejemplo, para que nuestra aplicación inicie automáticamente un `GenServer` `Contador` bajo supervisión:

```elixir
defmodule MyApp do
  use Application

  @impl true
  def start(_type, _args) do
    children = [
      {Contador, 0}   # el GenServer Contador se inicia con valor inicial 0
    ]

    # El supervisor raíz vigila a todos los hijos
    opts = [strategy: :one_for_one, name: MyApp.Supervisor]
    Supervisor.start_link(children, opts)
  end
end
```

Cuando se ejecuta `mix run`, Elixir llama a `start/2`, que arranca el supervisor raíz y este, a su vez, inicia el `Contador`.

Este patrón (una `Application` que inicia un árbol de supervisión) es la **base de toda aplicación OTP de producción** y es el que se espera en el proyecto final, donde un `DynamicSupervisor` gestiona las batallas creadas en tiempo de ejecución.

## Creación de pruebas 

Mix facilita la creación y ejecución de pruebas. Los archivos de prueba se colocan en el directorio `test`. Cree un archivo de prueba llamado `my_app_test.exs` en el directorio `test` con el siguiente contenido:

```elixir
defmodule MyAppTest do
  use ExUnit.Case # Importa las funcionalidades de ExUnit para pruebas

  test "la suma funciona correctamente" do
    assert 1 + 1 == 2
  end

  test "la resta funciona correctamente" do
    assert 2 - 1 == 1
  end

  test "la multiplicación no da un resultado incorrecto" do
    refute 2 * 3 == 7
  end

end
```

Toda prueba en Elixir se define dentro de un módulo que utiliza `ExUnit.Case`. La función `test` define una prueba individual, y dentro de ella se usan aserciones, que se explican más abajo.

Para ejecutar las pruebas, use el comando:

```bash
mix test
```

Debería salir un resumen de las pruebas ejecutadas, indicando cuántas pasaron y cuántas fallaron.

### Aserciones más comunes

ExUnit ofrece varias funciones para verificar condiciones dentro de una prueba:

- `assert expresion`: la prueba pasa si la expresión es verdadera.
- `refute expresion`: la prueba pasa si la expresión es falsa.
- `assert_raise TipoError, fn -> ... end`: verifica que el código lance una excepción del tipo indicado.
- `assert_in_delta valor1, valor2, delta`: verifica que dos números estén dentro de un margen (útil para flotantes).

```elixir
defmodule CalculadoraTest do
  use ExUnit.Case

  test "dividir por cero lanza una excepción" do
    assert_raise ArithmeticError, fn -> 1 / 0 end
  end

  test "el promedio es aproximadamente correcto" do
    assert_in_delta 10 / 3, 3.33, 0.01
  end
end
```

### Agrupar pruebas con `describe`

Cuando se tienen muchas pruebas relacionadas, se pueden agrupar con `describe`:

```elixir
defmodule CuentaTest do
  use ExUnit.Case

  describe "depositar/2" do
    test "aumenta el saldo" do
      assert Cuenta.depositar(100, 50) == 150
    end

    test "no acepta montos negativos" do
      assert Cuenta.depositar(100, -50) == {:error, :monto_invalido}
    end
  end
end
```

### Preparar datos con `setup`

El bloque `setup` se ejecuta **antes de cada prueba** y permite preparar datos comunes, que se reciben en un mapa de contexto:

```elixir
defmodule InventarioTest do
  use ExUnit.Case

  setup do
    inventario = %{"P001" => %{nombre: "Laptop", precio: 1200}}
    {:ok, inventario: inventario}   # se inyecta en el contexto de cada prueba
  end

  test "el producto existe", %{inventario: inventario} do
    assert Map.has_key?(inventario, "P001")
  end
end
```

> ⚠️ **Pruebas concurrentes:** Si las pruebas no comparten estado mutable, se puede usar `use ExUnit.Case, async: true` para que distintos módulos de prueba se ejecuten en paralelo, acelerando la ejecución.

```

├── lib/
```
