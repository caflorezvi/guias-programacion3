# Guards y manejo de resultados

En la guía anterior se estudiaron los operadores, las estructuras de decisión (`if`, `cond` y `case`) y una primera aproximación a la coincidencia de patrones (*pattern matching*). En esta guía se profundiza en esos conceptos para resolver un problema muy frecuente: **qué hacer cuando una operación puede fallar**.

Los temas que se abordarán son:

- Uso de *guards* (`when`) para seleccionar cláusulas de función.
- Atributos de módulo como constantes.
- Uso de tuplas `{:ok, valor}` y `{:error, motivo}` para representar resultados.
- La estructura `with` para encadenar operaciones que pueden fallar.
- Criterios para elegir entre `if`, `cond`, `case`, *guards* y `with`.

> ⚠️ **Importante:** los ejemplos de esta guía utilizan el módulo `Util` construido en la guía anterior. Asegúrese de tener el archivo `util.exs` compilado con `elixirc` en la misma carpeta donde ejecute los scripts.

## Ejemplo 1: Lotería

Se requiere un programa que simule una lotería básica, donde el usuario puede elegir un número entre **1 y 10**, luego el programa debe generar un número aleatorio en el mismo rango, determinar si el usuario ganó o no y cuál fue la diferencia. Si el usuario escribe un número fuera de este rango, el programa debe informarle que su elección es inválida y terminar.

Para generar números aleatorios en Elixir, se puede utilizar el módulo `:rand` de Erlang. Para más información, puede consultar la [documentación oficial](https://www.erlang.org/doc/apps/stdlib/rand.html).

### Versión 1

```elixir
defmodule Loteria do
  @minimo 1
  @maximo 10

  def main do
    "Ingrese un número entre #{@minimo} y #{@maximo}: "
    |> Util.leer(:integer)
    |> jugar()
    |> Util.imprimir()
  end

  defp jugar(numero) when numero >= @minimo and numero <= @maximo do
    numero
    |> calcular_diferencia()
    |> evaluar_resultado()
  end

  defp jugar(_), do: "Número no válido, fin del juego."

  defp calcular_diferencia(numero_usuario) do
    numero_ganador = :rand.uniform(@maximo) # Genera un número aleatorio entre 1 y @maximo
    abs(numero_usuario - numero_ganador) # Devuelve el valor absoluto de la diferencia
  end

  defp evaluar_resultado(0), do: "¡Felicidades, has ganado!"
  defp evaluar_resultado(diferencia), do: "Lo siento, has perdido. La diferencia fue de #{diferencia}."
end

Loteria.main()
```

Guarde el archivo como `loteria.exs` y ejecútelo con `elixir loteria.exs`. Al escribir un número dentro del rango, la sesión se ve así (lo que aparece después de los dos puntos es lo que usted escribe):

```
Ingrese un número entre 1 y 10: 7
Lo siento, has perdido. La diferencia fue de 2.
```

Como el número ganador se genera al azar, el resultado cambia en cada ejecución. Vuelva a correrlo varias veces hasta que le salga `¡Felicidades, has ganado!`.

Ahora pruebe con un número fuera del rango:

```
Ingrese un número entre 1 y 10: 15
Número no válido, fin del juego.
```

Ese segundo caso lo atiende la cláusula `jugar(_)`, ya que el *guard* de la primera no se cumple.

En esta implementación se usan dos **atributos de módulo**, `@minimo` y `@maximo`, para definir el rango de números válidos. La forma `@nombre valor` crea una **constante** con nombre, que no cambia durante la ejecución. Ajustar el rango más adelante solo exige tocarlo en un lugar.

Dos detalles más de este ejemplo:

- `:rand` es un **módulo de Erlang**, no de Elixir; por eso su nombre empieza con dos puntos. Es un ejemplo concreto de la interoperabilidad entre ambos lenguajes, ya que cualquier librería de Erlang puede usarse directamente desde Elixir.
- `:rand.uniform/1` es una **función impura** porque para la misma entrada devuelve resultados distintos en cada llamada. La impureza queda aislada en `calcular_diferencia/1`, mientras que `evaluar_resultado/1` permanece pura y, por lo tanto, es fácil de probar.

### Versión 2 (opcional)

La función `jugar/1` también puede escribirse de la siguiente manera:

```elixir
defp jugar(numero) when numero in @minimo..@maximo do
  numero
  |> calcular_diferencia()
  |> evaluar_resultado()
end
```

La diferencia es que se utiliza un rango de valores (`@minimo..@maximo`) en lugar de dos comparaciones unidas con `and`. La expresión `numero in @minimo..@maximo` indica de forma directa que el número debe estar entre el mínimo y el máximo, por lo que es la forma más común en Elixir.

## Ejemplo 2: Calculadora

Se requiere un programa que calcule las operaciones aritméticas básicas a partir de dos números ingresados por el usuario. Se debe validar que no se realice una división por cero. Cuando la operación sea válida, debe retornar `:ok` junto con el resultado, y en caso contrario debe retornar `:error` junto con un mensaje que indique el motivo.

```elixir
defmodule Calculadora do

  def main do
    numero1 = Util.leer("Ingrese el primer número: ", :integer)
    numero2 = Util.leer("Ingrese el segundo número: ", :integer)
    operacion = Util.leer("Escriba 1 para suma, 2 para resta, 3 para multiplicación, 4 para división: ", :integer)

    validar_operacion(numero1, numero2, operacion)
    |> mostrar_resultado()
  end

  defp validar_operacion(numero1, numero2, operacion) when operacion in 1..4 do
    operar(numero1, numero2, operacion)
  end

  defp validar_operacion(_, _, _), do: {:error, "Operación no válida."}

  defp operar(numero1, numero2, 1), do: {:ok, numero1 + numero2}
  defp operar(numero1, numero2, 2), do: {:ok, numero1 - numero2}
  defp operar(numero1, numero2, 3), do: {:ok, numero1 * numero2}
  defp operar(_numero1, 0, 4), do: {:error, "División por cero no permitida."}
  defp operar(numero1, numero2, 4), do: {:ok, numero1 / numero2}

  defp mostrar_resultado({:ok, resultado}), do: Util.imprimir("El resultado es: #{resultado}")
  defp mostrar_resultado({:error, mensaje}), do: Util.imprimir("Error: #{mensaje}", :error)

end

Calculadora.main()
```

Al ejecutarlo, cada camino del código produce una salida distinta. Una división normal:

```
Ingrese el primer número: 10
Ingrese el segundo número: 4
Escriba 1 para suma, 2 para resta, 3 para multiplicación, 4 para división: 4
El resultado es: 2.5
```

Una división por cero:

```
Ingrese el primer número: 10
Ingrese el segundo número: 0
Escriba 1 para suma, 2 para resta, 3 para multiplicación, 4 para división: 4
Error: División por cero no permitida.
```

Y una operación que no existe:

```
Ingrese el primer número: 10
Ingrese el segundo número: 4
Escriba 1 para suma, 2 para resta, 3 para multiplicación, 4 para división: 9
Error: Operación no válida.
```

Pruebe los tres casos antes de seguir leyendo e identifique qué cláusula produjo cada mensaje.

Las **tuplas** `{:ok, resultado}` y `{:error, mensaje}` permiten que cada función diga si la operación funcionó o no, y con la **coincidencia de patrones** `mostrar_resultado/1` separa los dos casos en cláusulas distintas. El resultado se imprime como un mensaje normal con `Util.imprimir/1`, mientras que el error se imprime con `Util.imprimir(mensaje, :error)`, que lo envía a la salida de errores. Observe que el átomo `:error` de la tupla es el que decide qué cláusula se ejecuta y, por lo tanto, cómo se imprime el mensaje.

En la cláusula `operar(_numero1, 0, 4)`, el `0` del patrón hace que coincida **solo cuando el segundo número es `0`**, detectando la división por cero antes de realizarla. Así, un mismo patrón puede combinar variables con valores concretos, como `0`, `:ok` o `:error`.

También importa **el orden de las cláusulas**. La de división por cero debe ir *antes* que `operar(numero1, numero2, 4)`, porque Elixir evalúa de arriba hacia abajo y ejecuta la primera que coincida. Si estuvieran al revés, la división por cero nunca se detectaría.

## Ejemplo 3: Registro de usuarios

Una plataforma necesita validar los datos de registro de un nuevo usuario. La validación debe realizarse en orden: el nombre no puede estar vacío, la edad debe ser un número válido y mayor o igual a 18, y el correo debe contener el carácter "@". Si todas las validaciones son correctas, se debe registrar al usuario; si alguna falla, se debe informar el motivo del error.

### Versión 1

```elixir
defmodule Registro do

  def main do
    nombre = Util.leer("Ingrese el nombre: ", :string)
    edad = Util.leer("Ingrese la edad: ", :string)
    email = Util.leer("Ingrese el email: ", :string)

    registrar(nombre, edad, email)
    |> mostrar_resultado()
  end

  defp registrar(nombre, edad, email) do
    with {:ok, nombre} <- validar_nombre(nombre),
         {:ok, edad} <- validar_edad(edad),
         {:ok, email} <- validar_email(email) do
      {:ok, "Usuario #{nombre} (#{edad} años, #{email}) registrado correctamente."}
    end
  end

  defp validar_nombre(""), do: {:error, "El nombre no puede estar vacío."}
  defp validar_nombre(nombre), do: {:ok, nombre}

  defp validar_edad(edad) do
    case Integer.parse(edad) do
      {numero, ""} when numero >= 18 -> {:ok, numero} # en la cláusula se puede usar un guard para validar la edad
      {_numero, ""} -> {:error, "El usuario debe ser mayor de edad."}
      _ -> {:error, "La edad no es un número válido."}
    end
  end

  defp validar_email(email) do
    if String.contains?(email, "@") do
      {:ok, email}
    else
      {:error, "El email debe contener el carácter '@'."}
    end
  end

  defp mostrar_resultado({:ok, mensaje}), do: Util.imprimir(mensaje)
  defp mostrar_resultado({:error, motivo}), do: Util.imprimir("Error de registro: #{motivo}", :error)

end

Registro.main()
```

Con datos válidos:

```
Ingrese el nombre: Carlos
Ingrese la edad: 32
Ingrese el email: caflorez@uniquindio.edu.co
Usuario Carlos (32 años, caflorez@uniquindio.edu.co) registrado correctamente.
```

Si la edad no llega a 18:

```
Ingrese el nombre: Ana
Ingrese la edad: 15
Ingrese el email: ana@uqvirtual.edu.co
Error de registro: El usuario debe ser mayor de edad.
```

Ahora haga fallar **las tres validaciones a la vez**, con el nombre vacío, una edad de 15 y un correo sin arroba:

```
Ingrese el nombre:
Ingrese la edad: 15
Ingrese el email: ana.correo.com
Error de registro: El nombre no puede estar vacío.
```

Solo se reporta el primer error, aunque los tres datos estén mal. Eso es lo que hace la estructura `with`, que encadena varias operaciones que pueden fallar:

- Cada línea usa el operador `<-`, que intenta hacer **coincidencia de patrones** entre el patrón de la izquierda (`{:ok, valor}`) y el resultado de la derecha.
- Si **todos** los patrones coinciden, se ejecuta el bloque `do` y se construye el mensaje de éxito.
- Si **alguno no coincide**, `with` **detiene la ejecución** y devuelve ese valor sin ejecutar el cuerpo. Por eso `mostrar_resultado/1` recibe la tupla de error e imprime el motivo con `Util.imprimir(mensaje, :error)`.

Sin `with`, cada validación requeriría anidar un `case` o un `if` dentro del anterior. Con `with`, las validaciones se escriben una debajo de la otra, por lo que es la estructura adecuada para encadenar funciones que retornan `{:ok, valor}` o `{:error, motivo}`.

### Versión 2

Se puede agregar un bloque `else` al `with` para manejar de forma explícita los valores que no coincidieron. Así, el mensaje de error se construye dentro del propio `with`, junto al mensaje de éxito:

```elixir
def main do
  nombre = Util.leer("Ingrese el nombre: ", :string)
  edad = Util.leer("Ingrese la edad: ", :string)
  email = Util.leer("Ingrese el email: ", :string)

  registrar(nombre, edad, email)
  |> mostrar_resultado()
end

defp registrar(nombre, edad, email) do
  with {:ok, nombre} <- validar_nombre(nombre),
       {:ok, edad} <- validar_edad(edad),
       {:ok, email} <- validar_email(email) do
    {:ok, "Usuario #{nombre} (#{edad} años, #{email}) registrado correctamente."}
  else
    {:error, motivo} -> {:error, "Error de registro: #{motivo}"}
  end
end

defp mostrar_resultado({:ok, mensaje}), do: Util.imprimir(mensaje)
defp mostrar_resultado({:error, mensaje}), do: Util.imprimir(mensaje, :error)
```

La salida es idéntica a la de la Versión 1 en todos los casos. Reemplace las dos cláusulas de `mostrar_resultado/1` de la Versión 1 por las de esta versión.

La diferencia está en **dónde se construyen los mensajes**. En la Versión 1, el texto `"Error de registro: ..."` se armaba en `mostrar_resultado/1`. Ahora `registrar/3` devuelve en ambos casos una tupla con el mensaje ya construido. El cuerpo del `with` devuelve `{:ok, mensaje}` y el `else` transforma el error en `{:error, mensaje}`. Así, `mostrar_resultado/1` solo se encarga de decidir por dónde imprimir, usando `Util.imprimir/1` para los mensajes de éxito y `Util.imprimir(mensaje, :error)` para los de error.

### Versión 3 (reto)

**Nuevo requerimiento:** la plataforma también pide una contraseña, que debe tener al menos 8 caracteres. Agregue la lectura de la contraseña en `main` y una cuarta validación al `with` de la Versión 2. La contraseña no debe aparecer en el mensaje de registro.

*Pista:* `String.length/1` retorna la cantidad de caracteres de una cadena.

Con datos válidos, el mensaje es el mismo de antes:

```

Ingrese el email: caflorez@uniquindio.edu.co
Ingrese la contraseña: elixir2026

```

Con una contraseña corta:

```

Ingrese la edad: 32
Ingrese el email: caflorez@uniquindio.edu.co
Ingrese la contraseña: abc123
```

## ¿Cuándo usar cada estructura?

A lo largo de la guía se presentaron varias estructuras de control y de decisión. La siguiente tabla resume cuándo conviene usar cada una:

| Estructura       | Úsela cuando...                                                                                            |
| ---------------- | ---------------------------------------------------------------------------------------------------------- |
| `if`             | Hay **una sola** condición booleana.                                                                       |
| `cond`           | Hay **varias condiciones independientes** y se ejecuta la primera que resulte verdadera.                   |
| `case`           | Se compara **un mismo valor** contra varios **patrones** (coincidencia de patrones).                       |
| `guard` (`when`) | Se quiere elegir la **cláusula de una función** (o de un `case`) según condiciones sobre los argumentos.   |
| `with`           | Se **encadenan varias operaciones que pueden fallar** y solo interesa continuar si **todas** tienen éxito. |

Los siguientes ejercicios **no incluyen una solución desarrollada**. Para cada uno, identifique qué estructura de control o técnica resulta más adecuada entre las vistas en esta guía y en la anterior.

### Ejercicio 1

Se necesita un programa en Elixir que solicite al usuario un código institucional y determine si es válido según las siguientes reglas:

- Debe tener exactamente 10 caracteres.
- Debe contener la cadena "UQ-" al inicio.
- Debe terminar en "2026".
  
Si cumple todas las condiciones, mostrar `{:ok, "Código válido"}`. De lo contrario, mostrar `{:error, "Código inválido: <razón del error>"}`, indicando todas las razones por las cuales el código no es válido.

Pista: se pueden usar las funciones `String.starts_with?/2`, `String.ends_with?/2` y `String.length/1` para validar el código.

### Ejercicio 2

Una cafetería del barrio quiere un programa que les indique a sus clientes si está abierta en este momento. El programa debe solicitar el día de la semana y la hora (un número entero entre 0 y 23), y responder según el siguiente horario de atención:

- De lunes a viernes: de 7 a 20.
- Sábados: de 8 a 22.
- Domingos: de 9 a 14.

La hora de cierre ya está por fuera del horario. De lunes a viernes, a las 20 la cafetería ya cerró y la última hora de atención es la de las 19.

El programa debe retornar:

- `{:ok, :abierta}` si la hora está dentro del horario de ese día.
- `{:ok, :por_cerrar}` si está dentro del horario, pero es la última hora antes de cerrar.
- `{:error, :cerrada}` si la hora está fuera del horario de ese día.
- `{:error, :dia_invalido}` si el día ingresado no corresponde a ninguno de la semana.

Resuelva el ejercicio escribiendo **una cláusula de función distinta para cada horario**, apoyándose únicamente en los *guards*, sin usar `if` ni `cond` dentro de ellas. Defina las horas de apertura y cierre con atributos de módulo, como se hizo en el Ejemplo 1.

Pista: normalice el día con `String.downcase/1` antes de compararlo, para que "Lunes" y "lunes" se traten igual. Recuerde además que un *guard* admite pertenencia a listas, como en `when dia in ["lunes", "martes"]`. Para la hora, la condición es `hora >= @apertura and hora < @cierre`, porque un rango como `@apertura..@cierre` incluiría la hora de cierre.
